# 한국어 문체 기준 (상시 적용)

한국어로 쓰는 모든 산출물 — 답변, 문서, 번역, 검수, 커밋 인접 산문 — 에 상시 적용하는 기준. 전역 CLAUDE.md가 이 파일을 참조한다: **세션에서 한국어 산출물을 처음 작성하기 전에 반드시 읽고, 세션 내내 적용한다.**

문장 원칙 → 금지 패턴 → 어휘 → 표기 → 말투 → 도메인 용어 순으로 구성한다. 어휘·표기 기준은 이 파일이 유일한 원본이다. 문서를 작성·번역·교정하는 작업에는 이 파일에 더해 korean-docs 스킬 전체(SKILL.md)와 심각도별 패턴 카탈로그([korean-style.md](korean-style.md))를 사용한다.

## 핵심 원칙

영어 문장 구조를 한국어 단어로 치환하지 않는다. 한국어로 다시 쓴다.

- 주어(you/we/it)는 생략하고 문장을 재구성한다.
- 피동보다 능동을 쓴다.
- 미래 단정("~할 것입니다")보다 현재형 단언("~합니다")을 쓴다.
- 확인한 사실은 단언한다. 헤징("~로 보입니다", "~일 수 있습니다")을 남발하지 않는다.

## 최우선 금지 패턴 (발견 즉시 고친다)

| 금지 | 대체 |
| ---- | ---- |
| 이중 피동: 되어진다, 보여진다 | 된다, 보인다 |
| ~하는 것을 허용합니다 / 가능하게 합니다 | ~할 수 있습니다 |
| 당신, 여러분, 우리는, 저희 | 생략하고 문장 재구성 |
| ~를 가지고 있다 (have 직역) | ~가 있다, ~를 제공한다 |
| 복수 "-들" 남발 (사용자들, 파일들) | 단수형으로 (맥락이 복수를 표현) |
| ~에 대해/~를 통해/~에 의해 남발 | 목적격 조사 직결, "~로", 행위자 주어 |
| 음차: 디폴트, 레버리지, 이슈(문제 의미) | 기본값, 활용, 문제 |
| 본질적으로, 결론적으로 (버릇말) | 삭제 또는 구체 서술 |
| ~할 것입니다 (will 직역) | ~합니다 |
| 그것은/그것이 (it 직역) | 생략 또는 명사 반복 |

## 직역·음차로 어색한 표현을 만들지 않는다

- **금지: "표면"(surface 직역)** — "문서 표면", "문서화 표면", "강한 표면" 같은 표현 금지. 맥락에 맞게 "문서 종류와 위치", "문서 구성", "문서 영역" 등 자연스러운 말로 대체한다.
- **금지: "계약"(contract 직역)** — `contract`는 정착된 프레임워크 용어이므로 영어 **"contract"** 로 둔다. "OpenAPI 계약", "생성된 계약" 같은 표현 금지. OpenAPI 소스 문서를 가리킬 때는 자연스러운 **"API 명세"** 또는 **"스펙"** 을 쓴다. (한국어에서 "계약"은 법적 합의로 읽혀 어색하며, 개념적 "팀 간 약속" 의미가 꼭 필요한 드문 경우에만 "계약(contract)"처럼 병기한다)
- 일반 명사·동사를 직역하거나 음차해 어색한 표현을 만들지 않는다. 예: "소비/소비하다(consume)"→"사용", "소비자(consumer)"→"사용하는 쪽/사용처", "평탄한(flat) DTO"→"DTO 그 자체", "방출하다(emit)"→"내보내다", "언래핑(unwrap)"→"벗겨내다", "와이어링(wiring)"→"연결", "엔트리(entry)"→"항목", "스캔 가능한(scannable)"→"한눈에 보기 쉬운", "형상"·"표면" 등.
- 영어 단어에 '-하다/-되다'를 붙여 한국어 동사로 만들지 않는다 (예: "인라인하다(inline)"→"직접 작성하다", "colocate되다"→"한 곳에 함께 두다", "resolve되다"→"~를 가리키다", "노출/숨김하다"→"표시하거나 숨기다", "import합니다"→"가져옵니다", "export합니다/됩니다"→"내보냅니다"). 단, `import`/`export`/`re-export`를 코드 구문 자체를 가리키는 **명사**로 쓰는 것은 허용한다(예: "서브패스 import로 통일", "re-export 파일").
- 영어 관용구를 일부만 직역하지 않는다 (예: "single source of truth"→"단일 소스" 금지; "단일 표준/유일한 출처/한 곳에서 관리"처럼 자연스럽게).
- **영어 비유(metaphor)·군사/게임 표현 직역 금지**: "X를 아군으로(make X an ally)"(✖)는 매우 어색 → "X를 강점으로/유리하게". "적이 아니라 아군"(✖) → "약점이 아니라 강점". ally→아군·enemy→적·battle→전투·war room→전시상황실 식 비유 직역을 피하고, 맥락에 맞는 평범한 한국어를 쓴다.
- 독자가 모를 수 있는 전문용어(예: "barrel/배럴")는 그대로 쓰지 말고 풀어 쓰거나 첫 등장 시 한 번 설명한다.

## 어색한 한자어·음차·직역 명사 → 일상 한국어

문서·주석 불문 적용한다. 권장 대체:

| 금지 | 대체 |
| ---- | ---- |
| 충실성 | 원문 충실도 |
| 거버너(governor 음차) | 감시기, 품질 감시기 |
| 함의(含意) | 뒷받침, 담고 있음 |
| 위상(topology) | 그래프 구조 |
| 동치(同値) | 일치 |
| 하니스, 하네스(harness 음차) | 실행 환경 (맥락에 따라 런타임, 제어 계층, 테스트 실행 환경, 평가 파이프라인) |
| 휴리스틱 | 경험 규칙 |
| 정련(精鍊) | 정제 |
| 다치(多値) 술어 | 다중값 술어 |
| 가역(可逆) | 되돌릴 수 있는, 되돌릴 수 있음 |
| 독립확증 | 독립 출처 확인 |
| 미지(未知) | 낯선, 처음 보는 |
| 자기 지지 | 자기 근거 |
| 전치(轉置) | 행·열 뒤바뀜 |
| 비싼 작업/신호, 싼 신호 | 비용이 큰 …, 비용이 적은 … |
| 나쁜 정보 | 잘못된 정보 |
| 답변에 안 떠오르게 | 답변에 나오지 않게 |
| 전제 위에 짓다 | 전제를 바탕으로 만들다 |
| 뽑다(추출 맥락) | 추출하다 |
| 붙는/붙이는 위치(where it hooks) | 적용 위치, 연결 지점 |
| 회수율(recall 직역) | 재현율 |

※ 정착된 음차(임베딩·토큰·그래프 등)와 별개 단어(예: "미지지=未支持, unsupported"는 "미지"와 다름)는 보존한다. 명사를 바꾸면 **뒤따르는 조사(은/는·이/가·을/를·과/와)를 받침에 맞춰 함께 고친다**.

## 표기법 (외래어 표기 오류)

디렉터리(✖디렉토리) · 라이선스(✖라이센스) · 릴리스(✖릴리즈) · 메시지(✖메세지) · 애플리케이션(✖어플리케이션) · 아키텍처(✖아키텍쳐) · 트랜잭션(✖트랜젝션) · 캐시(✖캐쉬) · 데이터(✖데이타) · 콘텐츠(✖컨텐츠) · 비즈니스(✖비지니스) · 컨트롤러(✖콘트롤러) · 메서드(✖메소드) · 알고리즘(✖알고리듬) · 템플릿(✖템플레이트) · 인터페이스(✖인터훼이스) · 스냅샷(✖스넵샷) · 타임스탬프(✖타임스템프) · 스레드(✖쓰레드) · 컬렉션(✖콜렉션) · 운영 체제(✖운영체제)

이 목록은 기본 용어사전(`GLOSSARY.base.md`)에 등재되어 감사 스크립트가 기계 검사한다. 영어 병기는 산출물당 첫 등장 1회만 하고, 이후에는 한국어만 쓴다.

## 과잉 교정 금지 (판단 기준)

- **정착된 외래어는 유지한다**: 어댑터, 콜백, 매핑, 슬롯, 스냅샷, 렌더(링), 파싱, 캐스팅, 네임스페이스, 리터럴, 핸들러, 메타데이터, 프리미티브 등은 한국어 개발에서 표준이다. 무리하게 순화하지 않는다.
- **정착된 영어 기술 용어는 원문 유지**: 제품명(Docker, Kubernetes), 언어명(Java), 약어(API, SQL), 프레임워크 용어(`hook`, `contract`, `entity`, `mutator`, `envelope`, `scaffold`). 음차("도커", "자바")도 금지.
- **직역이 아니라 의미로**: 영어 관용구·비유는 부분 직역하지 않고 맥락에 맞는 평범한 한국어로 옮긴다.

## 답변 말투

- 챗봇 잔재 금지: "좋은 질문이에요!", "도움이 되었으면 좋겠습니다", 과잉 공손, 아첨.
- 문두 접속사("또한", "따라서", "즉")를 문단마다 반복하지 않는다.
- 뻔한 결산 문장("결론적으로 ~라고 할 수 있습니다")으로 닫지 않는다. 내용으로 끝낸다.
- 기술 산출물과 답변에 이모지를 쓰지 않는다.

## 금융·퀀트·트레이딩 도메인 용어

금융/퀀트/트레이딩 도메인의 문서·코드·주석을 다룰 때 적용한다. 영어 용어를 음차하거나 직역해 어색한 표현을 만들지 않는다. 한국 금융 실무·학계에 정착된 용어를 쓰고, 정착 용어가 없으면 풀어 쓴다.

### 음차 남발 금지

| 금지 | 대체 |
| ---- | ---- |
| 브레드스(breadth) | 시장 폭 |
| 험프(hump) | (유동성 깊이) 정점 |
| 프린트(print, 체결 기록) | 체결값, 체결 기록 |
| 틸트(tilt) | 비중 기울임, 비중 확대 |
| 리더(leading stocks) | 주도주 |
| 헤드라인(headline 수치) | 대표 수치, 전체 |
| 오버레이(analysis overlay) | 보조분석 |
| 레짐(regime) | 국면 (시장 국면, 급락 국면, 국면 단절, 국면 게이트) |
| 드로다운(drawdown) | 낙폭, 급락 |

### 직역 금지·주의

- **"모사(模寫)" 금지** — `simulation`은 "시뮬레이션", 또는 정착 표현 "모의"(모의투자, 모의 체결)를 쓴다. "체결 모사" → "체결 시뮬레이션".
- **"함의(implied)" 금지** — "내재"를 쓴다. `implied volatility` → "내재 변동성", 내재 수익률, 내재 바스켓.
- **`effective` 번역 주의** — microstructure의 `effective spread`(2×|체결가−mid|)는 "유효 스프레드"로 정착돼 있으나, "실제 체결 가능한 호가차(executable bid/ask)"를 뜻할 때 "유효 스프레드"를 쓰면 혼동된다. 후자는 **"체결 가능 스프레드"**로 명시한다. `effective leverage`는 "실효 레버리지".
- **`regime break`** → "국면 단절" (econometrics 맥락은 "구조적 단절").
- **`book`(주문장) 직역 금지** — "책" 금지. "호가창"으로 쓴다("호가창이 얇아진다").
- **`dominated` 직역 주의** — "한국 지배(Korea-dominated)"(✖)는 "한국 주도"로. 시장 맥락의 `dominate`는 "지배"가 아니라 "주도".
- **`hard` 직역 주의** — "하드 손절" → "강제 손절", "하드 상한" → "절대 상한", "하드 레짐 단절" → "명백한 국면 단절". 단, "하드코딩"은 정착어로 유지.
- **영어 비유(metaphor) 직역 금지** — "plumbing→배관"(✖)은 "통제 체계/기반 규칙"으로, "let winners run→승자 주행"(✖)은 "수익 포지션을 끝까지 끌고 감"으로, "hazard sim→해저드 모사"(✖)는 "장애 시뮬레이션"으로, "aggressiveness dial→공격성 다이얼"(✖)은 "공격성 자동 조절"로 쓴다.
- **압축 직역 금지** — "단절 넘는 생존을 보고"(✖)처럼 영어 명사구를 압축 직역하지 말고 "단절 전후에도 살아남는지 확인한다"처럼 풀어 쓴다. "가산 선형(additive linear)" → "선형 합산", "비중복분(incremental/non-overlapping part)" → "중복되지 않는 부분, 추가 기여분".

### 정착 용어는 유지 (과잉 교정 금지)

엣지, 슬리피지, 레이턴시, 커버리지, 바스켓, 포지션, 프록시, 리밸런스, 잔차, 직교, 괴리, 편입/편출, 내재 변동성, 음의 자기상관, 실효 레버리지, 페어/스탯아브, 페이드(매매 맥락), 게이트 등은 그대로 쓴다.

처음 등장하는 전문 영어 약어·고유명(NBBO, OU, HAC, ATS 등)은 음차하지 말고 영문 그대로 두되, 필요하면 첫 등장 시 한 번 풀어 쓴다.

※ 기본 용어사전의 "레버리지 → 활용" 규칙은 이 도메인과 충돌한다. 금융 프로젝트의 용어사전에서는 `## 기본 규칙 예외`에 `레버리지`를 등재해 비활성화한다.

## 적용

- 작업 중인 프로젝트에 용어사전(`.claude/GLOSSARY.md` 또는 루트 `GLOSSARY.md`)이 있으면 답변에서도 그 표준 번역·금지 표기를 따른다. 프로젝트 용어사전은 이 파일의 기준과 충돌할 때 우선한다.
- 기존 텍스트에서 위반을 발견하면 touch-and-fix 원칙으로 자연스러운 표현으로 교체한다.
