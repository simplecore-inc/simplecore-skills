# Error Messages

How the message of a `SimpliXGeneralException` is written, stored, resolved and tested.

> **Scope (canonical):** the `{error.<domain>.<key>}` placeholder convention behind SKILL.md #3, the bundles that hold the keys, the translation-coverage test, and how unit tests assert a message. The audit rules `throw-time-english-default`, `throw-time-message-utils` and `banned-exception-type` check the Java side.

---

## Placeholders, bundles and tests

- **Message = `{error.<domain>.<key>}` placeholder, resolved ONLY at the HTTP layer.** Pass the literal placeholder (e.g. `"{error.channel.publishNotAllowed}"`); `SimpliXExceptionHandler` (the framework's envelope handler, which each project's `GlobalExceptionHandler` extends) resolves it to the request locale when building the response envelope. The exception constructor performs NO resolution, so `getMessage()` carries the raw key **by design** - everywhere below the HTTP layer, including logs and tests. **A message that carries arguments** (a count, a name) is the one case resolved at throw time: through `MessageUtils.get("error.<domain>.<key>", args)`, which the translation-coverage test scans, or through an injected `MessageSource`, whose bare key that test cannot see. Never an English literal. A message WITHOUT arguments resolved at throw time is the same defect in two spellings, and the audit flags both: `getMessage("error.x", null, "<English text>", locale)` (`throw-time-english-default`) and `MessageUtils.get("error.x")` inside a `throw`, an `orElseThrow` supplier or a `new <Name>Exception(...)` (`throw-time-message-utils`). A failure envelope a controller returns instead of throwing passes through no handler, so its text is resolved where it is built and is not flagged.
- **Error key bundles** live in `apps/<app>/src/main/resources/messages/errors*.properties` - add every new key to EVERY locale the project ships. The project's translation-coverage test (e.g. `ExceptionMessageTranslationTest` in the app module) scans source for `"{error.*}"` literals and `MessageUtils.get(...)` calls and fails the build on any key missing a translation or any cross-locale bundle drift - it is the single owner of message-text coverage.
- **Unit tests assert the message KEY, never resolved English prose** - `hasMessageContaining("error.channel.publishNotAllowed")`, not `hasMessageContaining("Publish")`. Mockito service tests have no Spring context: `{key}` placeholders stay raw, and `MessageUtils.get(key, args)` returns the code itself with args dropped (its static `MessageSource` is never initialized). English-prose assertions are valid ONLY for a message resolved at throw time through an injected `MessageSource` that the test stubs (`when(messageSource.getMessage(...)).thenReturn(...)`).
