# Customization Learnings (Staging)

> Staging area for framework- and pattern-level customization learnings that apply to any simplix-react project. Write new entries here with placeholders (`<prefix>`, `<domain>`, `<entity>`, `<EnumType>`) and neutral example vocabulary; fold an entry into the SKILL.md main body once it is stable. A learning specific to one project belongs in that project reference instead — see SKILL.md § Learnings from Trial and Error.

1. **A nullable enum in a detail row uses `DetailFields.DetailBadgeField`, never a bare badge inside `DetailFieldWrapper`.** Module badge shells (`StatusBadge`/`EnumBadge` wrappers over `resolveBootEnum`) return `null` for an absent value — correct in list cells and inline flex rows, but inside a `DetailFieldWrapper` it leaves a silently blank row while sibling `DetailFields.*` rows show the shared no-value badge. For a detail/dialog row whose enum can legitimately be absent (e.g. a match/verdict field that only exists when something matched), render it with `DetailBadgeField` (`value={resolveBootEnum(x) || null}` + `displayValue` + the module's variant map) so the empty state goes through the shared fallback. Mandatory-valued enum rows may keep the wrapper+badge shape.
