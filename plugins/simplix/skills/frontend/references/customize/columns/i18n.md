# List Column i18n Reference

Internationalization guide for `CrudList.Column` headers and cell content in the `@simplix-react` framework.

---

## i18n Requirements (MANDATORY)

**ALL user-facing text MUST use the i18n system. No hardcoded strings allowed.**

---

## Core Functions

### useEntityTranslation

The primary hook for entity field labels and enum labels.

```tsx
import { useEntityTranslation } from "@simplix-react/i18n/react";

const { fieldLabel, enumLabel } = useEntityTranslation("product");

// Column header
<CrudList.Column field="status" header={fieldLabel("status")} />

// Enum display in children render
{({ value }) => {
  const v = resolveBootEnum(value) as string;
  return <Badge>{enumLabel("ProductStatus", v)}</Badge>;
}}
```

### useTranslation

For custom strings not tied to entity fields. `useTranslation` comes from `@simplix-react/i18n/react` (NOT `react-i18next`) and **requires a namespace argument** — module widget strings use the `"<module>/widgets"` namespace; framework UI strings use `"simplix/ui"`.

```tsx
import { useTranslation } from "@simplix-react/i18n/react";

const { t } = useTranslation("<module>/widgets");

// Custom column header (key resolves within the namespace)
<CrudList.Column field="isVip" header={t("product.specialFlags")} />

// Custom text in children render
{({ value }) => value ? t("common.yes") : t("common.no")}
```

## Column Header Patterns

### Entity Field Label (Standard)

Use `fieldLabel()` for column headers that correspond to entity fields:

```tsx
const { fieldLabel } = useEntityTranslation("product");

<CrudList.Column field="name" header={fieldLabel("name")} />
<CrudList.Column field="status" header={fieldLabel("status")} />
<CrudList.Column field="categoryId" header={fieldLabel("categoryId")} />
```

### Custom Label (Non-Field Columns)

Use `t()` for columns that don't map directly to an entity field:

```tsx
const { t } = useTranslation("<module>/widgets");

<CrudList.Column field="isVip" header={t("product.specialFlags")} />
<CrudList.Column field="intervals" header={t("category.weeklyPreview")} />
<CrudList.Column field="type" header={t("product.productType")} />
```

## Enum Label Patterns

### Boot Enum with enumLabel

```tsx
import { resolveBootEnum } from "@simplix-react-ext/simplix-boot-utils";

const { enumLabel } = useEntityTranslation("product");

<CrudList.Column<ProductListDTO> field="status" header={fieldLabel("status")}>
  {({ value }) => {
    const v = resolveBootEnum(value) as string;
    return <Badge>{enumLabel("ProductStatus", v)}</Badge>;
  }}
</CrudList.Column>
```

**Key points:**
- First argument to `enumLabel` is the enum type name (e.g., `"ProductStatus"`)
- Second argument is the resolved string value (e.g., `"ACTIVE"`)
- Always use `resolveBootEnum()` to extract the string from boot enum objects

## Locale File Structure

### Domain Package Locale Files

Location: `packages/domain-*/src/locales/*.json`

These contain entity field labels and enum labels, auto-generated from the domain schema.

```
packages/domain-<domain>/src/locales/
  ├── en.json
  ├── ja.json
  └── ko.json
```

Example content (`en.json`):
Field labels live under `<entity>.fields.*`; enum labels live under a **single top-level `enums` namespace** (shared by the whole domain file), NOT nested inside the entity. `useEntityTranslation` reads field labels from the `entity/<entityName>` namespace and enum labels from the global `enums` namespace.

```json
{
  "product": {
    "fields": {
      "name": "Name",
      "status": "Status",
      "categoryId": "Category",
      "isVip": "VIP"
    }
  },
  "enums": {
    "ProductStatus": {
      "ACTIVE": "Active",
      "INACTIVE": "Inactive",
      "ARCHIVED": "Archived"
    }
  }
}
```

### Module Widget Locale Files

Location: `modules/*/src/locales/widgets/*.json`

These contain custom UI strings specific to widget implementations.

```
modules/<domain>/src/locales/widgets/
  ├── en.json
  ├── ja.json
  └── ko.json
```

Example content (`en.json`):
```json
{
  "product": {
    "specialFlags": "Special Flags",
    "productType": "Product Type"
  },
  "category": {
    "weeklyPreview": "Weekly Preview"
  }
}
```

## i18n Checklist

- [ ] Column headers use `fieldLabel()` for entity fields
- [ ] Column headers use `t()` for custom/composite labels
- [ ] Enum values use `resolveBootEnum()` + `enumLabel()` for display
- [ ] Boolean labels use `t()` (e.g., `t("common.yes")` / `t("common.no")`)
- [ ] Locale files exist for ko, en, ja in both domain packages and module widgets
- [ ] No hardcoded strings in column headers or cell content
