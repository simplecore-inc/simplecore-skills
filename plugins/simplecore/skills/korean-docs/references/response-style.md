# 한국어 문체 기준 (상시 적용)

한국어로 쓰는 모든 산출물 — 답변, 문서, 번역, 검수, 커밋 메시지 주변의 글 — 에 상시 적용하는 기준. 전역 CLAUDE.md가 이 파일을 참조한다: **세션에서 한국어 산출물을 처음 작성하기 전에 반드시 읽고, 세션 내내 적용한다.**

문장 원칙 → 금지 패턴 → 어휘 → 표기 → 말투 → 도메인 용어 순으로 구성한다. **어휘·표기·문체 기준은 이 파일이 유일한 원본이다** — 사용자가 지적한 표현도 여기 들어온다. 문서를 작성·번역·교정하는 작업에는 이 파일에 더해 korean-docs 스킬 전체(SKILL.md)와 심각도별 패턴 카탈로그([korean-style.md](korean-style.md))를 사용한다.

**사용자가 「이 표현은 잘못됐다」고 지적하면 그 자리에서 이 파일의 성격이 맞는 절에 한 줄 넣는다.** 지적받은 것만 모으는 절을 따로 두지 않는다 — 다음에 찾을 때 성격으로 찾지, 누가 지적했는지로 찾지 않는다. 그리고 **기계로 판정되는 것은 같은 변경에서 [`GLOSSARY.base.md`](../GLOSSARY.base.md)에 등재한다**(도메인과 무관하게 참일 때) 또는 작업 중인 프로젝트의 `.claude/GLOSSARY.md`에 등재한다(한 프로젝트에만 참일 때). 이 파일에만 적고 용어사전에 안 올린 규칙은 다음 세션에 잊힌다.

## 핵심 원칙

영어 문장 구조를 한국어 단어로 치환하지 않는다. 한국어로 다시 쓴다.

- 주어(you/we/it)는 생략하고 문장을 재구성한다.
- 피동보다 능동을 쓴다.
- 미래 단정(`~할 것입니다`)보다 현재형 단언(「~합니다」)을 쓴다.
- 확인한 사실은 단언한다. 헤징(`~로 보입니다`, `~일 수 있습니다`)을 남발하지 않는다.

## 최우선 금지 패턴 (발견 즉시 고친다)

| 금지 | 대체 |
| ---- | ---- |
| 이중 피동: `되어진다`, `보여진다` | 된다, 보인다 |
| `~하는 것을 허용합니다` / `가능하게 합니다` / `할 수 있게 해줍니다` | ~할 수 있습니다 |
| `~에 대한 지원을 제공합니다` | ~를 지원합니다 |
| `당신`, `여러분`, `우리는`, `저희` | 생략하고 문장 재구성 |
| `~를 가지고 있다` (have 직역) | ~가 있다, ~를 제공한다 |
| 복수 `-들` 남발 (`사용자들`, `파일들`) | 단수형으로 (맥락이 복수를 표현) |
| `~에 대해`/`~를 통해`/`~에 의해` 남발 | 목적격 조사 직결, 「~로」, 행위자 주어 |
| 음차: `디폴트`, `레버리지`, `이슈`(문제 의미) | 기본값, 활용, 문제 |
| `본질적으로`, `결론적으로` (버릇말) | 삭제 또는 구체 서술 |
| `~할 것입니다` (will 직역) | ~합니다 |
| `그것은`/`그것이` (it 직역) | 생략 또는 명사 반복 |
| `~에 산다`, `~에 삽니다`, `~에 사는`, `사는 곳` (lives 직역) | ~에 있다, ~에 둔다, ~에 남는다, 위치 |
| `사는 길이`, `살아 있는 길이` (기간) | ~하는 기간 |
| `구워 넣는다`, `구워져 있다` (baked into) | 이미지에 넣는다, 빌드에 들어 있다, 포함한다 |
| `역위상`, `위상 순서`, `위상 정렬` | 의존성 역순, 의존성 순서, 의존성 정렬 |

**상태 라벨을 문장 속에 그대로 끼워 넣지 않는다.** 화면의 상태 이름(`폐기됨`, `승인됨`, `보류`)은 그
자체로 완결된 라벨이라, 문장에 넣으면 조사가 붙지 않거나 이중 서술이 된다. 문장에서는 그 상태를
서술어로 풀어 쓴다.

| 금지 | 대체 |
| ---- | ---- |
| 제품 키가 `폐기됨`이 되고 | 제품 키가 폐기되고 |
| 주문이 `승인됨` 상태로 변경됩니다 | 주문이 승인됩니다 |
| 결제가 `실패`가 됩니다 | 결제가 실패합니다 |

라벨을 그대로 가리켜야 할 때만 따옴표나 UI 강조로 감싸 인용부호임을 드러낸다.

## 직역·음차로 어색한 표현을 만들지 않는다

- **금지: `표면`(surface 직역)** — 대체어는 무엇을 가리키느냐로 갈린다. **API가 여는 주소 묶음은 「엔드포인트」**다: `REST 표면`(✖) → 「REST 엔드포인트」, `목록 표면`(✖) → 「목록 조회 주소」, `엔티티를 받치는 표면`(✖) → 「엔티티를 받치는 엔드포인트」. **에이전트나 팀이 맡는 몫은 「맡은 범위」**다: `서버 표면`·`화면 표면`·`작업 표면`(✖) → 「서버 쪽」, 「화면 쪽」, 「맡은 범위」, 「건드리는 곳」. **문서의 갈래와 위치는 「문서 구성」**이다: `문서 표면`·`문서화 표면`(✖) → 「문서 종류와 위치」, 「문서 구성」, 「문서 영역」. 실제 사물의 겉면을 가리키는 쓰임(`배관 표면 온도`·`도장 표면`·`표면 처리`)은 올바른 용어라 유지한다.
  - **실제 겉면을 다루는 저장소에서 기본 규칙을 끄면 소프트웨어 쪽의 오용까지 함께 조용해진다.** 프로젝트 용어사전의 `## 기본 규칙 예외`는 저장소를 통째로 끄므로, 두 뜻이 한 저장소에 함께 있으면 예외를 켠 뒤에도 이 항목은 사람이 지켜야 한다 — 기계 쪽은 규칙 팩의 `software-surface`가 맡는다.
- **금지: `배선`·`재배선`(wiring 직역)과 `와이어링` 음차** — 소프트웨어 wiring은 문맥에 따라 옮긴다: 부트 시 객체 그래프를 짜맞추는 명사적 wiring은 **「조립」**(「프로덕션 조립」, 「조립 시점에 고정」), 컴포넌트를 경로·레지스트리에 꽂는 동사적 wiring은 **「등록」·「연결」**(「게이지 등록」, 「명령 경로에 등록」), dead wiring은 「연결되지 않은 경로」. 「연동」(런타임 상호 연계)·「통합」(integration)은 별개 개념이므로 wiring의 대역어로 쓰지 않는다. 전기를 잇는 실제 선로를 가리킬 때(`구리 배선`·`보드 배선`)는 `배선`이 올바른 용어라 유지한다.
- **금지: `전선`(on the wire 직역)** — 통신 경로를 `전선`이라 부르지 않는다. 한국어에서 `전선`은 전깃줄이다. `화면 문구를 전선에서 걷어낸다`(✖) → 「응답에서 뺀다」, `전선에 싣는다`(✖) → 「응답에 싣는다」, `전선이 나른다`(✖) → 「응답이 실어 나른다」. 실제 전깃줄·배전을 다루는 문서는 `전선`이 올바른 용어라 유지한다.
- **금지: `계약`(contract 직역)** — `contract`는 정착된 프레임워크 용어이므로 영어 **contract** 로 둔다. `OpenAPI 계약`·`생성된 계약` 같은 표현 금지. OpenAPI 소스 문서를 가리킬 때는 자연스러운 **「API 명세」** 또는 **「스펙」** 을 쓴다. (한국어에서 `계약`은 법적 합의로 읽혀 어색하며, 개념적 「팀 간 약속」 의미가 꼭 필요한 드문 경우에만 `계약(contract)`처럼 병기한다)
- 일반 명사·동사를 직역하거나 음차해 어색한 표현을 만들지 않는다. 예: `소비`·`소비하다`(consume) → 「사용」, `소비자`(consumer) → 「사용하는 쪽」·「사용처」, `평탄한`(flat) DTO → 「DTO 그 자체」, `방출하다`(emit) → 「내보내다」, `언래핑`(unwrap) → 「벗겨내다」, `엔트리`(entry) → 「항목」, `스캔 가능한`(scannable) → 「한눈에 보기 쉬운」, `형상`·`표면` 등.
  - **`소비자`는 낱말이 아니라 앞말로 갈린다.** 금지되는 것은 API·이벤트·메시지·큐·토픽의 consumer를 「소비자」라 부르는 쪽이고, 소비자물가·소비자 보호·최종 소비자·소비자원은 경제학과 법령의 정상 용어라 그대로 쓴다. 기본 용어사전의 `/소비(?!자)/`가 「소비자」를 뺀 것은 허용한다는 뜻이 아니라 **낱말 하나로는 두 뜻이 갈리지 않는다**는 뜻이다 — 기술 명사가 앞에 선 자리와 Kafka의 「소비자 그룹」은 규칙 팩의 `software-consumer`가 잡는다.
- 영어 단어에 `-하다`·`-되다`를 붙여 한국어 동사로 만들지 않는다 (예: `인라인하다`(inline) → 「직접 작성하다」, `colocate되다` → 「한 곳에 함께 두다」, `resolve되다` → 「~를 가리키다」, `노출하다`·`숨김하다` → 「표시하거나 숨기다」, `import합니다` → 「가져옵니다」, `export합니다`·`export됩니다` → 「내보냅니다」). 단, `import`/`export`/`re-export`를 코드 구문 자체를 가리키는 **명사**로 쓰는 것은 허용한다(예: 「서브패스 import로 통일」, 「re-export 파일」).
- 영어 관용구를 일부만 직역하지 않는다 (예: `single source of truth` → `단일 소스` 금지; 「단일 표준」·「유일한 출처」·「한 곳에서 관리」처럼 자연스럽게).
- **영어 비유(metaphor)·군사/게임 표현 직역 금지**: `X를 아군으로`(make X an ally)(✖)는 매우 어색 → 「X를 강점으로」·「X를 유리하게」. `적이 아니라 아군`(✖) → 「약점이 아니라 강점」. ally → `아군`, enemy → `적`, battle → `전투`, war room → `전시상황실` 식 비유 직역을 피하고, 맥락에 맞는 평범한 한국어를 쓴다.
- **작업을 가리키는 영어 동사의 비유를 그대로 옮기지 않는다.** 영어 문서가 일을 비유로 부르는 것은 흔하고, 그 비유는 한국어에서 대개 살아나지 않는다.

  | 영어 | 한국어 | 만들어진 말 |
  | ---- | ------ | ----------- |
  | walk (through a list, a board) | 처리한다, 훑는다, 작업한다 | `걷는다`, `걷기`, `걸은` |
  | build (an app, a binary) | 빌드한다, 만든다 | `세운다` |
  | stand up / start (a server) | 실행한다, 시작한다 | `세운다`, `띄운다` |
  | owe (a deliverable) | 요구한다, 필요하다 | `빚진다`, `빚는다` |

  **`세운다`가 걸리는 대상은 서버 · 설치 · 배포 · 계정 · 상태 · 커밋 · 빌드 · 컨테이너 · 이미지다.** 각각 실행한다 · 설치한다 · 배포한다 · 만든다 · 되살린다 · 커밋한다 · 빌드한다로 쓴다. **활용형 전부가 대상이다** — `세운다` · `세우고` · `세워` · `세우지` · `세울`. `계획을 세운다` · `규칙을 세운다` · `뼈대를 세운다`와 `판단이 서다`는 한국어에 굳어진 정상 표현이라 고치지 않는다.

  **`띄운다`는 대체어 자리에 두지 않는다.** 규칙 팩의 `launch-for-run`이 `서버를 띄`·`컨테이너를 띄`·
  `다시 띄우`를 오류로 잡으므로, 여기에 대체어로 적어 두면 이 파일이 규칙 팩이 막는 말을 권하게 된다 —
  그리고 그 자리는 감사에 걸리지 않는다(`띄운다` 한 낱말은 규칙의 어느 앞말과도 맞지 않는다). 화면
  요소는 `표시한다`·`연다`, 서버·컨테이너는 `실행한다`다.

  기본 용어사전이 잡는 것은 **`빚진다`·`빚는다`와 목적어가 붙은 `세운다`**(커밋 · 빌드 · 서버 · 컨테이너 · 이미지를 목적어로 삼은 자리)이다. `걷다`는 회비를 걷고 빨래를 걷는 정상 동사라 글자만으로 갈라지지 않으므로 사람이 문맥에서 판단한다.
- 독자가 모를 수 있는 전문용어(예: `barrel`·`배럴`)는 그대로 쓰지 말고 풀어 쓰거나 첫 등장 시 한 번 설명한다.

## 영어로 쓴 비유가 한국어 답장으로 돌아온다

**에이전트에게 보내는 영어 브리프에 비유를 쓰면, 그 비유가 한국어 문장으로 다시 나온다.** 영어 쪽에서는
`the app's own furniture` · `housekeeping` · `the ladder of resolution`이 평범한 관용이라 아무 검사도
걸지 않고, 옮기는 순간 「세간」 · 「살림」 · 「사다리」가 된다 — 이 셋 다 실제로 그렇게 나왔다.

**비유인 줄 모르는 이유는 자기가 방금 쓴 낱말이기 때문이다.** 남의 문서에서 읽은 비유는 눈에 띄는데,
한 시간 전 자기 브리프에 쓴 것은 이미 그 뜻으로 굳어 있어 번역이 아니라 회상이 된다.

**가르는 법은 하나다 — 같은 문장 안에 진짜 이름이 이미 있는가.**
「앱에는 자기 세간만 남는다 — 셸 · 내비 · 에러 · 라우트 접착」은 대시 뒤가 답이고 앞은 장식이라,
지우면 문장이 짧아지기만 한다. 진짜 이름이 없으면 그것부터 찾는다.

## 주어와 서술어를 맞춘다

**앞에 세운 주어가 뒤의 서술어와 맞지 않는 문장을 쓰지 않는다.** 요약하다가 두 문장을 한 문장으로
겹치면 이것이 나온다 — 주제로 세운 말과 실제로 움직이는 말이 다른데, 조사만 보고 지나가게 된다.

| 금지 | 무엇이 어긋났나 | 대체 |
| --- | --- | --- |
| `낱말은 아이디만 오고 화면이 꺼낸다` | 「오다」의 주어는 낱말이 아니라 아이디다 | 서버는 아이디만 보내고 낱말은 화면이 꺼낸다 |
| `이유가 편의가 아니다` | 주격 조사가 둘 — 「이유」와 「편의」가 같은 자리를 다툰다 | 편의 때문이 아니다 |

**고치는 길은 둘이다.** 움직이는 것을 주어로 세우거나(「서버는 ~ 보내고」), 겹친 문장을 도로 둘로
가른다. 주제를 앞에 두고 싶으면 그 주제가 실제로 하는 일을 서술어로 삼는다.

## 「재-」는 한자어에만 붙인다

**「재-」(again)는 한자어 명사에 붙는 접두사다.** 고유어에 붙이면 읽는 사람이 한 번 걸린다 —
말은 만들어지지만 한국어가 아니다.

| 금지 | 대체 | 왜 |
| --- | --- | --- |
| `재씨앗` | 씨앗을 다시 돌린다, 씨앗을 다시 심는다 | 「씨앗」이 고유어다 |
| `재걷기` | 다시 대조한다 | 「걷기」가 고유어다 |
| `재묶음` | 다시 묶는다 | 「묶음」이 고유어다 |

**한자어에 붙은 것은 그대로 쓴다** — 재검토 · 재발급 · 재처리 · 재색인 · 재인증은 정상이다.
금지의 기준은 「재-」가 아니라 **뒤에 오는 말이 고유어인가**이다.

**동작을 가리킬 때는 접두사보다 「다시 ~한다」가 낫다.** 명사로 굳혀야 할 이유가 없으면 풀어 쓴다.

## git의 작업 공간은 「나무」가 아니다

**working tree를 `나무`라 부르지 않는다.** `tree` 직역이고, 한국어로는 살아 있는 나무가 된다.

| 금지 | 대체 |
| --- | --- |
| `같은 나무에서 일한다` | 같은 작업 트리에서, 한 저장소에서 |
| `그 나무에 남의 작업이 있다` | 작업 트리에, 저장소에 |
| `마이그레이션 나무` | 마이그레이션 계보 |

**화면의 폴더 트리는 「트리」가 맞다** — UI에서 굳은 말이라 바꾸지 않는다. 금지되는 것은
git의 작업 공간과 디렉터리 구조를 `나무`로 옮기는 것이다.

## 「사람」은 사용자다 — 에이전트를 그렇게 부르지 않는다

**「사람」은 제품을 쓰는 사람, 결정을 내리는 사람이다.** 에이전트·세션·워커를 「사람」이라 부르면
그 구별이 무너지고, **「사람이 정할 일이다」가 뜻을 잃는다** — 그 문장은 사용자를 가리키는데,
읽는 에이전트가 자기더러 정하라는 말로 읽는다.

| 금지 | 대체 |
| --- | --- |
| `다음 사람이 다시 알아내지 않게` | 다음 에이전트가, 나중에 이 파일을 여는 쪽이 |
| `앞사람이 값을 치르고 배운 것` | 앞선 에이전트가 |
| `그 사람에게 넘겼다` (에이전트를 가리켜) | 그쪽에 넘겼다, 그 에이전트에 넘겼다 |

**문서를 읽을 상대가 사람인지 에이전트인지 모를 때는 「읽는 쪽」으로 쓴다.** 매뉴얼처럼 독자가
확실히 사람인 글에서는 「읽는 사람」이 맞다.

## 사물에 사람의 동작을 붙이지 않는다

**사물·추상이 주어일 때 사람이나 짐승의 동작을 서술어로 쓰지 않는다.** 살아 있는 글로 보이려다
어긋난 비유가 되고, 읽는 쪽은 무슨 일이 일어났는지를 한 번 더 새겨야 한다.

| 금지 | 대체 |
| --- | --- |
| `커밋이 남의 문단을 물고 갔다` | 커밋에 남의 문단이 함께 들어갔다 |
| `검사가 그 결함을 물었다` | 검사가 그 결함을 검출했다 |
| `화면이 값을 삼켰다` | 화면이 값을 버렸다, 값이 화면에 표시되지 않았다 |
| `서버가 쥔 키`, `주문이 순서를 쥐고` | 서버의 키 · 서버가 가진 키, 주문이 순서를 정하고 |

**`쥐다`는 손이 있는 쪽만 한다.** 서버·주문·목록이 무엇을 `쥔다`고 쓰지 않는다 — 가진다·갖는다,
또는 그냥 「~의」로 쓴다. 사람이나 조직이 주어인 `키를 쥔 쪽`·`개인키를 쥐고도`는 정상이므로
낱말을 통째로 금지하지 않는다. 가르는 것은 낱말이 아니라 **주어에 손이 있는가**이다.

**손만이 아니라 몸 전체가 그렇다.** 이 판단을 `쥐다` 하나에만 걸면 나머지 신체가 그대로 새어
나간다 — 동작이 아니라 **자리와 소유**로 붙는 쪽이 특히 그렇다.

| 금지 | 왜 | 대체 |
| --- | --- | --- |
| `그들 발밑에서 값이 바뀐다` | 에이전트에게 발이 없다 | 그들이 읽고 있는 동안 값이 바뀐다 |
| `에이전트가 눈으로 확인한다` | 소프트웨어에 눈이 없다 | 화면이 실제로 그려지는지 확인한다 |
| `초기화기가 그 행에 손대지 않는다` | 초기화기에 손이 없다 | 그 행을 건너뛴다 |
| `어깨너머로 본다`, `등 뒤에서` | 위치를 몸으로 잡았다 | 옆에서 함께 읽는다, 나중에 |

**몸이 있어야 하는 동사도 같다.** 앞의 표는 신체를 자리와 소유로 붙인 것이고, 이쪽은 동작이
몸을 요구하는 것이다 — 걷다·뛰다·기어가다. 소프트웨어가 무엇을 `걷지` 않는다.

| 금지 | 왜 | 대체 |
| --- | --- | --- |
| `페르소나 줄을 걷는다` | 줄은 길이 아니고 에이전트에게 다리가 없다 | 그 줄을 실행한다 |
| `마법사가 목록을 걷는다` | 같다 | 목록을 그대로 따라간다 |
| `걷지 않은 가이드워드` | 가이드워드는 적용하는 것이다 | 적용하지 않은 가이드워드 |
| `이 결함이 걸어서 지나가는 판정` | 결함에 다리가 없다 | 이 결함이 우회하는 판정 |

**이름이 이미 있는 자리가 대부분이다.** 「줄을 걷는다」가 가리키던 것은 `실행한다`이고, 「사다리를
걷는다」가 가리키던 것은 설계서가 이미 `3계층 해석`이라 부르는 것이다.

**사람이 주어이면 몸은 그대로 쓴다.** `한 손으로 읽는다`(전화 화면), `사람 눈에 맡긴다`,
`브라우저를 연 사람`, `현장을 걷는 관리감독자`는 전부 정상이다 — 몸이 있는 쪽이 주어이기 때문이다.
산업안전 문서의 `발밑을 확인한다`·`시야를 가린다`도 실제 사람의 몸이므로 건드리지 않는다.

**에이전트는 특히 걸리기 쉽다.** 보고하고 물러나고 판단하므로 사람처럼 쓰게 되는데, 그 동사들은
연산의 서술이라 정상이고 **몸은 아니다**. 「에이전트가 찾았다」는 되고 「에이전트 손에 쥐어 준다」는
안 된다.

`덮다`·`흘리다`처럼 사물에 이미 굳은 말은 그대로 쓴다. 새 비유를 지어내지 않는 것이 규칙이다.

**다만 고친 결과가 또 다른 비유이면 고친 것이 아니다.** `물고 갔다`를 `딸려 갔다`로, `말한다`를
`밝힌다`로, `삼켰다`를 `닿지 않았다`로 바꾸는 것은 같은 자리를 다른 비유로 옮긴 것뿐이다 —
실제 동작(함께 들어갔다 · 안내한다 · 표시되지 않았다)을 적는다. 화면에 나가는 문구는 이 판단이 더
엄격해서, `잡다`·`걸리다`처럼 문서에서는 굳은 말도 [ui-copy.md](ui-copy.md)가 실제 처리 내용으로
펴게 한다.

## 업무를 물리적 움직임으로 옮기지 않는다

**조건·적용·전달·상태를 물건이 움직이는 그림으로 쓰면, 읽는 쪽이 실제 동작을 추론해야 한다.**
같은 비유가 문서마다 다른 뜻으로 읽히는 것이 문제이지 문장이 짧은 것이 문제가 아니라서, 비유를
매끄럽게 다듬는 대신 **실제 동작을 가리키는 동사로 바꾼다.**

| 비유 | 무엇인지 확인한다 | 대체 |
| --- | --- | --- |
| 무엇에 **`기대다`** | 선행 조건인가 운영 조건인가 | ~해야 한다, 유지 조건, 추가 조건이 없다 |
| 정책·의무가 **`걸리다` · `딸리다`** | 적용인가 차단인가 | ~에 적용된다, ~에 포함된다 |
| 값을 **`싣다` · `싣고 오다`** | 포함인가 공급인가 전송인가 | ~를 포함한다, ~를 공급한다 |
| 조건이 **`무너지다`** | 미충족인가 해제인가 | 충족하지 않는다 |
| 단계가 **`열리다` · `막히다`** | 진행 가능인가 자동 시작인가 | 진행할 수 있다, 진행할 수 없다 |
| 서버로 **`올라가다`**, 단말로 **`내려오다`** | 전송인가 저장 완료인가 | 전송한다, 내려받는다 |
| 모드로 **`올리다` · `내리다`** | 등급인가 변경인가 | ~ 모드로 변경한다 |
| 기준이 대상을 **`가르다`** | 분류인가 제외인가 | ~에 따라 구분한다 |
| **`닿다` · `닿는 길` · `닿는 곳`** | 전달인가 연결인가 적용인가 접근인가 | 수신한다, 연결한다, 적용된다, 접근한다, 채널 |
| 순서를 **`사다리`**로 부르기 | 자동인가 수동인가, 마지막은 무엇인가 | 대체 순서, 우선순위, 마지막 채널 |
| 역할·조직·기능을 **`자리`**로 부르기 | 조직인가 역할인가 화면인가 | 소속 조직, 필수 역할, 설정 화면 |

**실제 물리 동작은 그대로 둔다** — 출입문이 열리고, 손이 벽에 닿고, 사다리를 놓는 것은 비유가
아니다. 수치가 한계에 이르는 것은 `한도에 닿는다`가 아니라 **「한도에 도달한다」**로 쓴다.

**설명하는 쪽이 가장 자주 쓰는 비유는 원인과 제거다.** 답변·검토 보고·설계 노트에 잘 남는다.

| 금지 | 대체 |
| --- | --- |
| `그 행이 뿌리입니다`, `문제의 뿌리` | 그 행이 원인입니다, 원인 |
| `도메인이 배어든 것`, `배어 있다` | 도메인 용어가 섞인 것, 섞여 있다 |
| `도메인을 걷어낸다` | 도메인 용어를 뺀다, 제거한다 |
| `그 자리를 짚는다` | 그 자리를 지적한다 |

**프로세스가 사는 것과 죽는 것은 한 계열이다 — 한쪽만 고치면 반대쪽이 정상으로 읽힌다.**

| 금지 | 대체 |
| --- | --- |
| `에이전트가 죽었다`, `죽은 에이전트` | 에이전트가 중단됐다, 멈춘 에이전트 |
| `프로세스를 죽인다` | 프로세스를 종료한다 |
| `세션이 살아 있다`, `살아 있는 컨테이너` | 세션이 유효하다, 실행 중인 컨테이너 |
| `빌드가 살아났다`, `되살렸다` | 빌드가 다시 동작한다, 복구했다 |
| `서버의 생사` | 서버가 응답하는지 |

**사람과 동물이 실제로 죽는 것은 이 계열이 아니다.** 산업안전·의료·보험 문서의 「사망 재해」·
「사망자」·「중대재해」·「사망하거나 영구 장해」는 도메인의 정식 용어이므로 그대로 쓴다 — 실제
사망을 비유로 지적하는 오탐 하나가 규칙 전체를 꺼지게 하고, 비유 하나를 놓치는 것은 그러지 않는다. 그래서 규칙 팩의
`process-as-alive`는 어간이 아니라 **주어가 소프트웨어 구성물일 때만** 잡는다.

**두 가지 사이의 관계를 그림 한 낱말로 부르지 않는다.** 무엇이 같고 무엇이 다른지가 사라진다.

| 금지 | 대체 |
| --- | --- |
| `거울상이다` | 방향만 반대인 같은 결함이다 |
| `판박이다` | 똑같다 |
| `데칼코마니다` | 좌우가 뒤집힌 같은 배치다 |
| `동전의 양면이다` | 같은 규칙의 두 방향이다 |
| `쌍둥이다` | 구조가 같다 |

실물은 그대로 쓴다 — 광학·화학의 「거울상 이성질체」(enantiomer), 실제 거울, 실제 동전, 판박이
스티커, 실제 쌍둥이.

**서술어는 있는 그대로 가리키는 말을 고른다** — 적용·포함·등록·저장·전송·동기화·표시·구분·확인·
선택·제출·승인·제한·차단·완료·취소·복구·충족·발생·유지·조회·변경·삭제. 범위가 넓은
동사(처리·진행·관리)도 남용하지 않고, 더 정확한 동작을 알 수 있으면 검토·승인·서명·배포·폐기로
좁힌다.

화면에 나가는 문구는 이 기준에 더해 [ui-copy.md](ui-copy.md)를 적용한다.

## 간접의문절에 「입니다」를 붙이지 않는다

**`~인지입니다`·`~한지입니다`·`~할지입니다`·`~볼지입니다`는 의문절을 명사 서술어처럼 끝낸
번역체다.** 영어 `This is about whether…`의 어순만 옮긴 것이라 문법으로는 해석돼도 한국어 문장으로는
서지 않는다. 무엇을 확인하거나 설정하는지를 그대로 적는다.

| 금지 | 대체 |
| --- | --- |
| `누구에게 무엇이 나갔고 언제까지 유효한지입니다` | 사용자별 지급 내역과 유효기간을 확인합니다 |
| `어느 상표로 보일지입니다` | 콘솔·앱·출력물에 표시할 상표를 설정합니다 |
| `지금도 검증되는지, 언제까지 검증될지입니다` | 현재 검증 상태와 검증 가능 기간을 확인합니다 |

**`가지입니다`·`기한입니다`·`별지입니다`는 완성된 명사라 대상이 아니다** — 마지막 글자만 보고
고치지 않는다.

## 어색한 한자어·음차·직역 명사 → 일상 한국어

문서·주석 불문 적용한다.

**표에 없는 말을 판정하는 물음은 「이 분야에서 굳은 말인가」다.** 아래 항목들이 이미 한 가족이다 —
`전치`는 선형대수, `동치`와 `함의`는 논리학, `위상`은 위상수학, `정련`은 야금, `가역`은 열역학의
말이다. **다른 분야에서 굳은 한자어를 이쪽으로 데려오면 읽는 사람이 그 분야의 뜻을 먼저 지우고 다시
읽어야 하고**, 그 한 번이 이 표가 막으려는 것 전부다.

**그러니 표는 목록이 아니라 예시다.** 새 말을 만나면 항목을 찾지 말고 이렇게 묻는다.

1. **이 분야 문서에서 이미 쓰이는 말인가** — 검출 · 판정 · 대조 · 조회 · 전송 · 재처리는 소프트웨어
   한국어로 굳었다. 그대로 쓴다.
2. **다른 분야에서 온 말인가** — 그러면 그 분야의 뜻이 따라온다. 「전사(轉寫)」는 언어학의 음성 전사와
   생물학의 전사에서 온 말이라, 화면에 있는 것을 옮겨 적는 일을 가리키면 읽는 사람이 두 번 푼다.
   **「받아 적은 것」이 같은 뜻이고 더 짧다.**
3. **더 짧은 일상 한국어가 같은 뜻인가** — 그러면 그쪽이다. **없으면 바꾸지 않는다.**

**3번이 과잉 교정을 막는 자리다.** 「어댑터」·「콜백」·「캐시」를 한국어로 풀어 쓰지 않는 것과 같은
이유이고, 한국어로 보이게 만들려고 바꾸는 것은 이 규칙이 아니다.

| 금지 | 대체 |

**이 표는 기본 용어사전에 등재되어 기계가 검사한다.** 뜻이 갈리는 낱말은 정상 쓰임을 앞뒤 글자로
빼서 등재했다 — `함의`는 서술어(함의한다·함의하는)와 「논리적 함의」를, `가역`은 「가역 반응」·
「가역과정」을, `미지`는 미지수·미지급·미지불·미지지·미지원·미지정·미지근을, `전치`는 전치사·
전치증폭기·전치태반을, `동치`는 동치관계·동치류를, `충실성`은 회계의 「표현의 충실성」을, `휴리스틱`은
HCI의 「휴리스틱 평가」를, `자기 지지`는 「자기 지지대」·「자기 지지체」를 뺀다. 빠진 형태까지 정식
용어로 쓰는 도메인(회계·금속 공정·선형대수·열역학·수학)은 프로젝트 용어사전의 `## 기본 규칙 예외`로
해당 행을 끈다.

**세 낱말은 등재하지 않고 사람이 본다.** 대체어가 없어서가 아니라 정상 쓰임과 글자가 같아서다.

| --- | --- | --- |
| `뽑다`(추출 맥락) | 「후보를 뽑는다」·「번호표를 뽑는다」가 정상어다 | 없음 |

## 제목과 목록 항목의 문말

문서 본문을 「~한다」로 쓰는 규칙은 **서술문에 대한 것이다.** 제목·목차 항목·표의 이름 열·메뉴
항목처럼 이름이 서는 자리에 그 문말을 쓰면 문장을 자르다 만 것처럼 읽힌다. 이름 자리는 명사형이다.

| 금지 | 대체 |
| --- | --- |
| `시작한다` (제목) | 시작하기, 시작 |
| `자료를 넣는다` (제목) | 자료 넣기 |
| `설치하고 운영한다` (제목) | 설치와 운영 |
| `근거를 파고든다` (제목) | 근거 파고들기 |

**제목은 자리가 정해져 있어 기계가 판정한다.** 같은 「~한다」가 본문에서는 정상이라 문장 일반으로는
가를 수 없지만, `^#`로 시작하는 줄은 마크다운이 이름 자리로 정해 둔 곳이다 — 감사
엔진의 `heading-form`이 그 줄만 읽어 경고로 보고하고, 인용부호나 백틱으로 감싼 제목(남의 문장을
그대로 옮긴 것)과 낱말 하나짜리 제목(용어를 세우는 자리)은 뺀다. 표의 이름 열·메뉴 항목처럼 마크다운
제목이 아닌 이름 자리는 여전히 사람이 본다.

**오류가 아니라 경고인 까닭은 명사형이 손해인 문서가 있기 때문이다.** 규칙서에서는 제목이 곧 규칙
문장인 편이 가장 알아보기 쉽고, 그런 저장소는 프로젝트 용어사전의 `## 기본 규칙 예외`에
`heading-form`을 적어 끈다. **끌 때는 사유를 같은 행에 적는다** — 사유가 없으면 다음에 여는 쪽이
판단이 내려진 것인지 누가 검사를 꺼 둔 것인지 구별할 수 없다.

**질문도 이름 자리에 서지 않는다.** `무엇을 하는가`·`무엇에 기대는가`·`어떻게 흐르는가`는
영어 제목의 직역이고, 한국어 제목은 찾는 정보를 명사로 부른다 — `무엇에 기대는가` → 유지 조건,
`어디로 올라가는가` → 전송 위치, `무엇을 쥐고 있는가` → 표시되는 정보. **남길 수 있는 질문형은 읽는
사람이 실제로 입 밖에 내어 묻는 형태뿐이다**(「누가 승인할 수 있나요?」). `~는가`로 끝나는 제목은
대개 쓴 사람이 스스로에게 던진 질문이고, 그것은 제목이 아니라 그 아래에 답할 내용이다.

## 과잉 교정 금지 (판단 기준)

- **정착된 외래어는 유지한다**: 어댑터, 콜백, 매핑, 슬롯, 스냅샷, 렌더(링), 파싱, 캐스팅, 네임스페이스, 리터럴, 핸들러, 메타데이터, 프리미티브 등은 한국어 개발에서 표준이다. 무리하게 순화하지 않는다.
- **정착된 영어 기술 용어는 원문 유지**: 제품명(Docker, Kubernetes), 언어명(Java), 약어(API, SQL), 프레임워크 용어(`hook`, `contract`, `entity`, `mutator`, `envelope`, `scaffold`). 음차(`도커`, `자바`)도 금지.
- **직역이 아니라 의미로**: 영어 관용구·비유는 부분 직역하지 않고 맥락에 맞는 평범한 한국어로 옮긴다.

## 답변 말투

- 챗봇 잔재 금지: `좋은 질문이에요!`, `도움이 되었으면 좋겠습니다`, 과잉 공손, 아첨.
- 문두 접속사(`또한`, `따라서`, `즉`)를 문단마다 반복하지 않는다.
- 뻔한 결산 문장(`결론적으로 ~라고 할 수 있습니다`)으로 닫지 않는다. 내용으로 끝낸다.
- 기술 산출물과 답변에 이모지를 쓰지 않는다.

**채팅에 쓴 답변은 아무도 검사하지 않는다.** 쓰기 시점 훅은 파일을 읽으므로, 답변으로 친 문장은
기계가 뒤에 서 있지 않은 유일한 자리다. 그래서 이 파일의 여섯 가지 판정은 파일보다 답변에 더
자주 필요하다.

**보고를 옮겨 적는 것은 인용이 아니다.** 서브에이전트가 올린 보고, 실행 기록, 남이 쓴 메모를
사용자에게 전할 때 그 서술의 낱말을 그대로 쓰면 옮긴 쪽의 문장이 된다 — 기준은 옮긴 문장에도
똑같이 적용된다. 글자 그대로 인용하는 것은 화면 라벨, 오류 메시지, 파일에 실제로 있는 문자열,
문서 제목처럼 **어딘가에 그 글자로 존재하는 것**뿐이고, 받은 보고를 요약해 전하는 서술은 여기
해당하지 않는다.

**가장 위험한 자리는 브리프에 적어 보낸 낱말을 서브에이전트가 그대로 쓴 보고다.** 스스로 만든
말이라 낯설지 않아 답변에서 그대로 통과하고, 같은 낱말이 그 에이전트가 고친 문서에도 남는다. 한
낱말이 브리프 → 보고 → 답변 → 문서 네 자리에 퍼지는 데 한 세션이면 충분하므로, **브리프를 쓸 때가
그 낱말을 마지막으로 고를 수 있는 자리다.**

**반대 방향이 더 자주 일어나고, 검사가 그것을 엉뚱한 사람에게 보고한다.** 올린 보고를 읽은 쪽이 그
문장을 제 문서에 옮겨 적으면, 금지 표기는 **옮겨 적은 사람의 파일에서** 걸린다. 쓴 사람은 그 검출을
보지 못하고, 본 사람은 자기가 고른 낱말이 아니라 고칠 근거를 모른다 — 실제로 한 저장소가 용어사전에
「게이트 → 검사」를 두고 문서 380곳을 그렇게 쓰고 있었는데, 보고가 「게이트」로 적어 보낸 문장이
그대로 옮겨져 원장에서 오류가 났다.

**그러니 보고에도 프로젝트 용어사전을 적용한다.** 채팅은 아무 검사도 읽지 않지만 채팅에 쓴 문장은
남의 파일로 걸어 들어간다. **특히 그 저장소가 자기 기계 장치를 부르는 이름**(검사 · 단계 · 대장)은
보고에서 영어나 음차로 바꿔 부르지 않는다 — 코드 식별자는 백틱에 넣어 그대로 쓰고, 그것을 가리키는
한국어 낱말은 저장소가 쓰는 낱말로 적는다.

## 금융·퀀트·트레이딩 도메인 용어

금융/퀀트/트레이딩 도메인의 문서·코드·주석을 다룰 때 적용한다. 영어 용어를 음차하거나 직역해 어색한 표현을 만들지 않는다. 한국 금융 실무·학계에 정착된 용어를 쓰고, 정착 용어가 없으면 풀어 쓴다.

### 음차 남발 금지

| 금지 | 대체 |
| ---- | ---- |
| `브레드스`(breadth) | 시장 폭 |
| `험프`(hump) | (유동성 깊이) 정점 |
| `프린트`(print, 체결 기록) | 체결값, 체결 기록 |
| `틸트`(tilt) | 비중 기울임, 비중 확대 |
| `리더`(leading stocks) | 주도주 |
| `헤드라인`(headline 수치) | 대표 수치, 전체 |
| `오버레이`(analysis overlay) | 보조분석 |
| `레짐`(regime) | 국면 (시장 국면, 급락 국면, 국면 단절, 국면 게이트) |
| `드로다운`(drawdown) | 낙폭, 급락 |

**낱말로 등재된 것은 넷뿐이다** — `브레드스` · `험프` · `레짐` · `드로다운`. 나머지 다섯은 금융 밖에서
쓰는 뜻이 정상어라(인쇄하는 프린트, 카메라의 팬·틸트, 팀 리더와 카드 리더, 기사 헤드라인, 화면
오버레이) 낱말만으로는 갈리지 않으므로, 갈라 주는 앞말과 함께 등재했다: `체결 프린트` · `비중 틸트` ·
`가치 틸트` · `팩터 틸트` · `모멘텀 틸트` · `리더 종목` · `헤드라인 수치` · `헤드라인 지표` ·
`분석 오버레이`. **앞말이 없는 자리는 사람이 본다** — 금융 문서에서 이 다섯 낱말을 만나면 무엇을
가리키는지 확인하고 위 표의 대체어로 고친다.

### 직역 금지·주의

- **`모사(模寫)` 금지** — `simulation`은 「시뮬레이션」, 또는 정착 표현 「모의」(모의투자, 모의 체결)를 쓴다. `체결 모사` → 「체결 시뮬레이션」.
- **`함의`(implied) 금지** — 「내재」를 쓴다. `implied volatility` → 「내재 변동성」, 내재 수익률, 내재 바스켓.
- **`effective` 번역 주의** — microstructure의 `effective spread`(2×|체결가−mid|)는 「유효 스프레드」로 정착돼 있으나, 「실제 체결 가능한 호가차」(executable bid/ask)를 뜻할 때 「유효 스프레드」를 쓰면 혼동된다. 후자는 **「체결 가능 스프레드」**로 명시한다. `effective leverage`는 「실효 레버리지」.
- **`regime break`** → 「국면 단절」 (econometrics 맥락은 「구조적 단절」).
- **`book`(주문장) 직역 금지** — `책` 금지. 「호가창」으로 쓴다(「호가창이 얇아진다」).
- **`dominated` 직역 주의** — `한국 지배`(Korea-dominated)(✖)는 「한국 주도」로. 시장 맥락의 `dominate`는 `지배`가 아니라 「주도」.
- **`hard` 직역 주의** — `하드 손절` → 「강제 손절」, `하드 상한` → 「절대 상한」, `하드 레짐 단절` → 「명백한 국면 단절」. 단, 「하드코딩」은 정착어로 유지.
- **영어 비유(metaphor) 직역 금지** — plumbing → `배관`(✖)은 「통제 체계」·「기반 규칙」으로, let winners run → `승자 주행`(✖)은 「수익 포지션을 끝까지 끌고 감」으로, hazard sim → `해저드 모사`(✖)는 「장애 시뮬레이션」으로, aggressiveness dial → `공격성 다이얼`(✖)은 「공격성 자동 조절」로 쓴다.
- **압축 직역 금지** — `단절 넘는 생존을 보고`(✖)처럼 영어 명사구를 압축 직역하지 말고 「단절 전후에도 살아남는지 확인한다」처럼 풀어 쓴다. `가산 선형`(additive linear) → 「선형 합산」, `비중복분`(incremental/non-overlapping part) → 「중복되지 않는 부분, 추가 기여분」.

### 정착 용어는 유지 (과잉 교정 금지)

엣지, 슬리피지, 레이턴시, 커버리지, 바스켓, 포지션, 프록시, 리밸런스, 잔차, 직교, 괴리, 편입/편출, 내재 변동성, 음의 자기상관, 실효 레버리지, 페어/스탯아브, 페이드(매매 맥락), 게이트 등은 그대로 쓴다.

처음 등장하는 전문 영어 약어·고유명(NBBO, OU, HAC, ATS 등)은 음차하지 말고 영문 그대로 두되, 필요하면 첫 등장 시 한 번 풀어 쓴다.

※ 기본 용어사전의 `레버리지 → 활용` 규칙은 이 도메인과 충돌한다. 금융 프로젝트의 용어사전에서는 `## 기본 규칙 예외`에 `레버리지`를 등재해 비활성화한다. **이 기준을 적어 두는 저장소도 마찬가지다** — 도메인 용어를 지정하려면 그 낱말을 적어야 하므로, 이 파일을 담은 저장소의 용어사전에도 같은 예외가 필요하다. 기준을 적었다는 이유로 기준을 어긴 것이 되면 스킬이 제 감사를 통과할 수 없다.

## 적용

- 작업 중인 프로젝트에 용어사전(`.claude/GLOSSARY.md` 또는 루트 `GLOSSARY.md`)이 있으면 답변에서도 그 표준 번역·금지 표기를 따른다. 프로젝트 용어사전은 이 파일의 기준과 충돌할 때 우선한다.
- 기존 텍스트에서 위반을 발견하면 touch-and-fix 원칙으로 자연스러운 표현으로 교체한다.
