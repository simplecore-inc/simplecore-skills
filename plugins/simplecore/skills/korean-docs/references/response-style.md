# 한국어 문체 기준

한국어로 쓰는 모든 산출물(답변 · 문서 · 번역 · 검수 · 화면 문구)에 적용한다. **한국어를 처음 쓰기 전에
읽고, 긴 세션에서 요약이 일어난 뒤에는 다시 읽는다.** 읽었다는 기억은 근거가 아니다. 아래 문체 표와
여덟 물음을 지금 인용할 수 없으면 읽지 않은 것이다.

**기계가 검사하는 것은 여기 적지 않는다.** 표기(디렉터리 · 라이선스 · 애플리케이션), 음차 금지어,
고유명, 금지 단어는 `GLOSSARY.base.md`와 `RULES.base.json`에 있고, 감사 스크립트와 쓰기 시점 훅이
검사한다. 이 파일은 기계가 판정하지 못하는 것, 곧 문장을 쓰는 쪽이 판단할 것만 적는다. 작업 중 새
용어나 금지 표기를 정했으면 이 파일이 아니라 용어사전이나 규칙 팩에 등재한다
([audit-tooling.md](audit-tooling.md)).

## 1. 문체

| 산출물 | 문체 | 예 |
| --- | --- | --- |
| 채팅 답변 · 설명 · 보고 | 합니다체. 사용자에게 하는 요청은 「~해 주세요」 | 확인했습니다 · 디스크를 먼저 비워 주세요 |
| 설계 · 개발 문서 (작업 문서) | -다체 평서문. 프로젝트 용어사전이 다르게 정하면 그쪽을 따른다 | 이 화면은 목록을 표시한다 |
| 매뉴얼 · 독자용 설명문 | 합니다체, 독자 지시는 「~하세요」 | 저장을 누르세요 |
| 화면 문구 | 합니다체. 버튼과 항목명은 명사구 또는 짧은 동작 | 저장할 수 없습니다 · 저장 |
| 제목 · 표 머리 · 메뉴 · 라벨 | 명사형. 마침표 · 질문형 · 「~한다」를 쓰지 않는다 | 시작하기 · 유지 조건 |

- **사용자의 말투를 따라 하지 않는다.** 반말 · 줄임말 · 욕설로 물어도 답변은 합니다체다. `비워 달라` ·
  `알려 달라` · `실행해 달라`는 답변에 쓰지 않는다.
- 문장은 서술어와 종결어미로 닫는다. 명사구 · 부사구 · 연결어미로 끝내지 않는다. 이름을 적는 곳(제목 ·
  라벨)만 예외이고, 거기에는 마침표를 찍지 않는다.
- 챗봇 잔재(`좋은 질문이에요` · `도움이 되었으면 좋겠습니다`)와 이모지를 쓰지 않는다. 결산 문장으로
  닫지 않고 내용으로 끝낸다.

## 2. 문장을 내보내기 전 여덟 물음

하나라도 「예」이면 다듬지 않고 다시 쓴다.

| # | 물음 | 걸리는 예 → 고친 예 |
| --- | --- | --- |
| 1 | 몸이 없는 것이 말하고 묻고 기억하고 판단하는가 | `화면이 알려 줍니다` → 화면에 표시합니다 · `규칙이 스스로 구분합니다` → 규칙으로 자동 판정합니다 · `기록이 오래 산다` → 기록이 오래 남는다 |
| 2 | 움직이지 않는 것이 움직이는가, 관계를 물건 다루듯 쓰는가 | `알림이 갑니다` → 알림을 보냅니다 · `서버로 올라간다` → 서버로 전송한다 · `담당과 기한을 붙인다` → 지정한다 · `두 값이 부딪힌다` → 충돌한다 · `사업장이 손댄 것` → 고친 것 |
| 3 | 이름이 있는 것을 비유로 부르는가, 변화를 부사로 감추는가 | `관문을 연다` → 요건을 충족하면 진행할 수 있다 · `통째로 바뀝니다` → 어느 항목이 어떻게 바뀌는지 적는다 · `이 화면의 동사다` → 이 화면이 하는 일이다 |
| 4 | 영어 문장을 단어만 바꿔 옮겼는가 | `되어진다` → 된다 · `~하는 것을 가능하게 합니다` → ~할 수 있습니다 · `~를 가지고 있다` → ~가 있다 · `~에 대해 설명` → ~를 설명 · `~할 것입니다`(사실) → ~합니다 · `당신` · `우리는` · `그것은` · `-들` 삭제 |
| 5 | 주어와 서술어가 맞는가, 여러 주어에 한 서술어가 다 맞는가 | `낱말은 아이디만 오고 화면이 꺼낸다` → 서버는 아이디만 보내고 낱말은 화면이 꺼낸다 · `12곳은 전부 상한이고` → 12곳은 전부 상한을 뜻한다 · `톨루엔과 소음은 마신 양이 아니다` → 두 문장으로 나눈다 |
| 6 | 확인한 사실에 헤징이 붙었는가, 버릇말이 있는가 | `~로 보입니다` · `~인 것 같습니다` → 단언한다 · `본질적으로` · `결론적으로` · `요약하면` → 삭제 · 문단마다 `또한` · `따라서` · `즉` → 문장 흐름으로 잇는다 · `강력한` · `획기적인` → 수치와 사실 |
| 7 | 조사 · 어미 · 성분이 빠졌는가, 서술어로 닫혔는가, 「의」가 겹쳤는가 | `컨텍스트 압축 전 신중 반영한다` → 컨텍스트가 압축되기 전에 신중하게 반영합니다 · `승인 요청이 반려됨.` → 승인 요청을 반려했습니다 · `값을 확인하고.` → 값을 확인하고 넘어갑니다 · `사본의 문구는 작업의 상황을` → 사본에 기재된 문구는 작업이 진행되는 상황을 |
| 8 | 이 분야 사람이 쓰지 않는 말이 있는가, 대시가 관계를 감추는가 | `견주다` → 비교하다 · `갈무리하다` → 저장하다 · `일컫다` → 부르다 · `여쭈다`(기계 동작) → 조회하다 · `기본값을 두었다 — 검증이 건너뛰어진다` → 기본값을 그대로 두면 검증을 건너뜁니다 |

**3번의 명사.** `자리` · `몫` · `천장` · `바닥` · `함정` · `관문` · `사다리` · `갈래` · `길` · `연료` · `씨앗`이
실제 이름이 있는 것을 대신하면 그 이름으로 바꾼다. 소속 조직 · 필수 역할 · 설정 화면 · 유형 · 상한 ·
대체 순서처럼 제 이름을 쓴다. 실제 물건(출입문 · 벽보 · 사다리)은 비유가 아니다.

**5번은 요약에서 생긴다.** 두 문장을 하나로 겹치면 앞의 주제와 실제로 움직이는 것이 달라진다.
움직이는 것을 주어로 세우거나 두 문장으로 나눈다. 개수를 세고 뜻을 붙이는 문장(`8곳 중 7곳은 정상`)은
「~이 쓰인 7곳은 정상 용법이다」처럼 무엇을 가리키는지 적는다.

**7번은 「짧게 쓰라」에 반응할 때 생긴다.** 한국어는 조사와 어미부터 잃는다. 관계(`~가 압축되기 전에`)와
빠진 성분(무엇에 경고가 표시되는지)을 적고 서술어로 닫는다. 「의」를 겹쳐 쓰면 서술어가 설 곳이
없어진다(`화면의 항목의 이름` → 화면 항목의 이름).

**8번의 대시.** 인과 · 역접 · 조건을 대시로 잇지 않고 접속어로 적는다. 동격 · 열거 · 이름 뒤의 설명은
대시가 관계를 감추지 않으므로 그대로 둔다. 화면 문구에는 대시를 쓰지 않는다.

## 3. 단어를 고르는 기준

- **정착한 외래어와 기술 용어는 그대로 둔다.** 어댑터 · 콜백 · 매핑 · 슬롯 · 캐시 · 핸들러 · 메타데이터 ·
  네임스페이스 · 리터럴, API · SQL, Docker · Kubernetes · Java(원문). 한국어로 보이게 하려고 바꾸지
  않는다. 프레임워크 용어(`hook` · `contract` · `entity`)도 원문으로 둔다.
- **더 짧은 일상어가 같은 뜻일 때만 바꾼다.** 뜻이 빠지면 바꾼 것이 아니다. `쓴 비용을 구하는 함수`는
  지출과 추론이 사라졌으므로 「지출한 비용을 추론하는 함수」가 맞다.
- **다른 분야에서 굳은 한자어를 데려오지 않는다.** `함의` · `동치` · `정련` · `가역` · `위상` · `전치` ·
  `전사`는 논리학 · 야금 · 열역학 · 수학 · 언어학의 말이라 읽는 쪽이 그 분야의 뜻을 먼저 지워야 한다.
  소프트웨어 한국어로 굳은 말(검출 · 판정 · 대조 · 조회 · 전송 · 재처리)은 그대로 쓴다. 등재된 것은 기계가
  잡고, 새 말은 「이 분야 문서에서 이미 쓰는가」로 판정한다.
- **영어 관용구와 비유를 직역하지 않는다.** single source of truth → `단일 소스` ✖ 「한 곳에서 관리」,
  make X an ally → `X를 아군으로` ✖ 「X를 강점으로」, walk (a list) → `걷는다` ✖ 「처리한다 · 훑는다」,
  stand up (a server) → `세운다` ✖ 「실행한다」, on the wire → `전선` ✖ 「응답에」, working tree →
  `나무` ✖ 「작업 트리」, surface → `표면` ✖ 「엔드포인트 · 맡은 범위」, wiring → `배선` ✖ 「조립 · 등록」.
  실제 동작을 가리키는 동사를 고른다.
- **영어 브리프의 비유는 한국어 답변으로 돌아온다.** `furniture` → `세간`, `ladder` → `사다리`처럼 한
  시간 전 자기가 쓴 비유는 회상이 되어 걸러지지 않는다. 브리프에서 진짜 이름을 쓴다. 같은 문장 안에 진짜
  이름이 이미 있으면 비유는 장식이므로 지운다.
- **영어 단어에 `-하다` · `-되다`를 붙이지 않는다.** `인라인하다` → 직접 작성하다, `resolve되다` → ~를
  가리키다, `export합니다` → 내보냅니다. `import` · `re-export`를 코드 구문의 이름으로 쓰는 것은 허용한다.
- **「재-」는 한자어에만 붙인다.** 재검토 · 재발급은 정상이고 `재걷기` · `재묶음`은 「다시 대조한다 · 다시
  묶는다」로 쓴다.
- **「사람」은 사용자다.** 에이전트 · 세션 · 워커는 「에이전트」, 독자가 사람인지 에이전트인지 모르면
  「읽는 쪽」으로 쓴다. `다음 사람이 다시 알아내지 않게` → 다음 에이전트가.
- **사물에 몸의 동작을 붙이지 않는다.** `서버가 쥔 키` → 서버의 키, `커밋이 물고 갔다` → 커밋에 함께
  들어갔다, `에이전트가 눈으로 확인한다` → 화면이 실제로 그려지는지 확인한다, `목록을 걷는다` →
  실행한다. 사람이 주어이면 몸은 그대로 쓴다. 고친 결과가 또 다른 비유(`딸려 갔다` · `밝힌다`)이면 고친
  것이 아니다.
- **프로세스는 살거나 죽지 않는다.** `에이전트가 죽었다` → 중단됐다, `프로세스를 죽인다` → 종료한다,
  `살아 있는 컨테이너` → 실행 중인 컨테이너. 산업안전 · 의료 문서의 실제 사망은 정식 용어다.
- **검사와 규칙은 울지 않는다.** `검사가 운다` → 검출한다 · 보고한다. 경보 · 알람 · 벨은 실제로 소리를
  내므로 그대로 쓴다.
- **상태 라벨을 문장에 끼우지 않는다.** `제품 키가 폐기됨이 되고` → 제품 키가 폐기되고. 라벨 자체를
  가리킬 때만 따옴표로 감싼다.
- **간접의문절에 「입니다」를 붙이지 않는다.** `언제까지 유효한지입니다` → 유효기간을 확인합니다.
- **관계를 그림 한 단어로 부르지 않는다.** `거울상이다` → 방향만 반대인 같은 결함이다, `판박이다` →
  똑같다, `동전의 양면이다` → 같은 규칙의 두 방향이다.
- **서술어는 있는 그대로 가리키는 말을 고른다.** 적용 · 포함 · 등록 · 저장 · 전송 · 표시 · 구분 · 확인 ·
  승인 · 차단 · 완료 · 복구 · 조회 · 변경 · 삭제. 처리 · 진행 · 관리처럼 넓은 동사보다 더 정확한 동작을
  알 수 있으면 그 동작을 쓴다.
- **갈라 써야 하는 단어.** 결제(값을 치름)와 결재(승인 절차) · 정산(지급)과 대사(장부 대조) · 프로필(사용자)과
  프로파일(실행 환경) · 절대 시각 · 달력 날짜 · 현지 시각(`Instant` · `LocalDate` · `LocalTime`).

## 4. 답변과 보고

- **채팅 답변은 아무 검사도 거치지 않는다.** 쓰기 시점 훅은 파일만 읽는다. 그래서 2절의 여덟 물음은
  파일보다 답변에 더 자주 필요하고, 감사가 0건을 낸 직후의 답변도 예외가 아니다.
- **보고를 옮겨 적는 것은 인용이 아니다.** 서브에이전트의 보고, 실행 기록, 남의 메모를 사용자에게
  전하면 그 문장은 전하는 쪽의 문장이고 같은 기준을 받는다. 글자 그대로 인용하는 것은 화면 라벨 · 오류
  메시지 · 파일에 실제로 있는 문자열 · 문서 제목처럼 어딘가에 그 글자로 존재하는 것뿐이다.
- **보고에도 프로젝트 용어사전을 적용한다.** 그 저장소가 자기 장치를 부르는 이름(검사 · 단계 · 대장)을
  영어나 음차로 바꿔 부르지 않는다. 코드 식별자는 백틱에 넣어 그대로 쓴다.
- **브리프에 쓴 단어가 보고를 거쳐 답변과 문서까지 퍼진다.** 브리프를 쓸 때가 그 단어를 고를 마지막
  기회다.

## 5. 지적받은 표현은 지침을 진단한다

사용자가 문장을 짚으면 그 문장은 증상이고 진단 대상은 이 파일과 규칙이다. 단어를 금지 목록에 올리기
전에 셋을 확인한다.

1. 어느 규칙이 잡았어야 했는데 왜 못 잡았나. 형태만 열거했거나, 한 모양에만 앵커를 걸었거나, 오탐을
   피하려다 나머지를 잃었으면 유형으로 넓힌다.
2. 지침 자신이 그 표현을 쓰고 있지 않나. 대체어 열, 예문, 지침의 문장이 그 말을 쓰면 답변도 그 말을
   쓴다. **지침을 지침 자신으로 먼저 검사한다.**
3. 유형이 아예 없나. 그러면 빠진 규칙이다. 유형을 이름 짓고 정상 쓰임과 가르는 판정법을 함께 적는다.

원인을 고친 뒤, 기계가 판정할 수 있는 것은 용어사전이나 규칙 팩에 경계와 hit/miss 예문과 함께
등재한다. 보고에 셋 중 무엇이었는지 적는다. 자주 나오고 자가 교정이 실패한 단어는 등재하되, 그 항목이
목록에 없는 문장도 판정할 수 있어야 규칙이다.

## 6. 도메인 용어
