# 감사 도구 참조 — l10n.mjs · 훅 · 선언 파일 · 규칙 작성

감사를 실행하거나, 규칙을 만들고 고치거나, 남이 보고한 검출을 확인할 때 읽는다. 문장을 쓰는 기준은
[response-style.md](response-style.md)에 있고, 이 파일은 도구가 무엇을 어떻게 검사하는지만 다룬다.

## 도구는 하나, 규칙 원천은 둘

`scripts/l10n.mjs` 하나가 문서와 다국어 자원을 같은 규칙으로 검사한다.

| 원천 | 파일 | 검사 대상 | 읽는 명령 |
| --- | --- | --- | --- |
| 용어사전 | `GLOSSARY.base.md` + 프로젝트 `.claude/GLOSSARY.md` | 표기 · 음차 · 고유명 · 금지 단어 (단어 단위) | `check` · `audit` · 쓰기 시점 훅 |
| 규칙 팩 | `RULES.base.json` + 프로젝트 `.claude/l10n-rules.json` | 문장 패턴 (정규식, hit/miss 예문 필수) | `rules` |
| 렌즈 | `references/lens.txt` | 규칙이 좁아 놓치는 것을 사람이 읽을 후보로 넓게 뽑는다 | `grep --regex` |

```bash
T="$HOME/.claude/skills/simplecore/skills/korean-docs/scripts/l10n.mjs"
node "$T" check [경로...]        # 문서 감사 — audit.paths 대상, 없으면 프로젝트 전체 (훅과 같은 판정)
  --all             # audit.paths 무시하고 프로젝트 전체
  --strict          # 경고도 실패 처리
  --untranslated    # 영문 문장 잔존 경고 (번역 프로젝트)
  --glossary <p>    # 용어사전 경로 직접 지정
  --no-base         # 기본 용어사전 제외
  --list-rules      # 병합된 규칙 확인 (등재 결과 대조)
  --init            # .claude/GLOSSARY.md 템플릿 생성
  --init-l10n       # .claude/l10n.json + .claude/l10n-rules.json 뼈대 생성
node "$T" audit [--kind K]       # 자원 감사 — 번역 누락 · 금지 표기 · 조사 · 짝 언어 파일
node "$T" rules --test           # 규칙 팩이 제 hit/miss 예문을 통과하는지 검증
node "$T" rules [--scope S]      # 문장 규칙으로 자원을 훑는다 (고치지 않는다)
node "$T" suspects [--json]      # 문체가 어색한 문장을 점수순으로 뽑는다
node "$T" grep <패턴> [--regex]  # 자원의 문구 값에서 찾는다
node "$T" list                   # 선언이 실제로 잡는 파일 목록
node "$T" apply --patch <파일>   # 다시 쓴 문장 목록을 반영한다 (--write 전까지 미리보기)
```

`scripts/check-glossary.mjs`는 같은 엔진의 훅 진입점이라 `check`와 판정이 같다.

**일괄 치환 명령은 없고 만들지 않는다.** 규칙은 단어의 위치만 알고 문맥은 모른다. 고칠 위치를 네
명령으로 뽑고, 문맥을 읽고 다시 쓴 문장을 `apply --patch`로 넣는다. 저장된 원문이 파일과 다르면
반영을 거절한다.

## 용어사전이냐 규칙 팩이냐

둘 중 하나라도 해당하면 규칙 팩이고, 둘 다 아니면 용어사전이다.

1. 금지할 것이 활용하는 용언이다.
2. 정상 쓰임과 가르는 예외를 적어야 한다.

2번만으로도 규칙 팩이다. `거울상` · `판박이`는 활용하지 않는 명사지만, 광학의 「거울상 이성질체」와
「판박이 스티커」를 빼는 예외는 용어사전 행에 적을 수 없다. 용어사전 행은 hit/miss 예문도 예외도 못
적으므로, 활용하는 말을 거기 넣으면 적어 둔 한 형태만 검출되고 나머지 활용형은 지나간다.

| 넣을 것 | 위치 |
| --- | --- |
| 표기 · 음차 · 오탈자 | 용어사전 |
| 프로젝트가 정한 대역어와 금지 표기 | 프로젝트 용어사전 |
| 활용하는 용언 | 규칙 팩 |
| 예외를 적어야 하는 것 | 규칙 팩 |

## 용어사전 형식

- 표 형식(열 구성, `/pattern/` 정규식, `,` 구분, 셀 안 `|` 금지, 정규식 안 `,` 금지)을 지켜야 파싱된다.
- `금지 표현`의 `수준`은 `오류` · `경고` · `경고(N+)`(한 파일에서 N회 이상일 때만 보고) 셋뿐이다.
  다른 표기는 파싱 오류다.
- `경고(N+)`는 「금지 → 대체」 대조 행의 대체 쪽을 세지 않는다.
- 등재한 뒤 `--list-rules`로 그 행이 의도한 패턴과 수준으로 나오는지 대조한다. 스크립트는 정규식
  오류 · 수준 표기 · 열 밀림만 알려 준다.
- front matter 설정: `audit.paths` · `audit.exclude` · `audit.localeResources` · `audit.untranslated` ·
  `audit.resolvedPlaceholders`.
- 명시적으로 지정한 파일은 `audit.exclude`를 무시하고 검사한다. 용어사전 파일 자체는 검사하지 않는다.
- 코드 블록 · 인라인 코드 · 링크 경로 · URL은 검사에서 제외된다. **금지 표현의 표본은 인라인 코드에
  넣는다.** 「」 안은 일반 문장으로 읽으므로, 규칙을 설명하는 문서가 「」로 표본을 적으면 자기 규칙에
  걸린다. 「」는 화면 라벨 · 용어 · 문서 제목처럼 이름을 가리킬 때 쓴다.

### 기본 규칙 커스터마이징

`GLOSSARY.base.md`는 전 프로젝트 공유라 고치지 않는다. 프로젝트 용어사전에서 조정한다.

- **대체**: 같은 `영어` 키의 행을 정의하면 기본 행 전체가 교체된다. 유지할 금지 표기는 함께 옮겨 적는다.
- **비활성화**: `## 기본 규칙 예외` 표에 영어 키(행 전체) 또는 패턴 텍스트(개별 규칙)를 적는다. 패턴
  텍스트는 공백 · 기호까지 정확히 일치해야 하며, 맞지 않으면 `check`가 「죽은 예외」로 보고한다.
- **내장 검사 끄기**: 같은 표에 `heading-form` · `repeat` · `untranslated`를 적는다. 끌 수 있는 것은
  경고 수준뿐이다. 오류 수준의 조사 검사(`particle` · `interpolated-particle` · `reference-particle`)는
  적으면 설정 오류로 거절한다. 끈 검사는 실행마다 이름이 출력된다.
- **끄지 말고 좁히기**: 한 곳에서만 옳은 인용 때문에 규칙 전체를 끄지 않는다. `.claude/l10n-rules.json`의
  `except`에 `find` · `why` · `sample`을 적으면 그 검출 위치만 놓아 준다. `rules --test`가 규칙이
  `sample`을 잡는지, 예외가 그 위치를 덮는지 증명한다.

```json
"except": {
  "loanword-spelling": [{
    "find": "/어플리케이션 응답시간/",
    "why": "제안요청서 요구사항명 원문. 고치면 인용이 아니게 된다",
    "sample": "| PER-001 | 어플리케이션 응답시간 |"
  }]
}
```

### 남의 문서를 그대로 옮긴 구간 — `l10n:quote`

제안요청서 원문, 표준 조문, 법령 조항처럼 글자 그대로 옮기는 것이 요건인 구간은 표시로 감싸고 사유를
함께 적는다.

```markdown
<!-- l10n:quote 제안요청서 SFR-003 원문 -->
정의: 클러스터 노드별 태스크 분배, 장애 시 절체 및 복구 후 재분배 기능 제공
<!-- l10n:/quote -->
```

- `check` · `rules` · `suspects`가 같은 구간을 건너뛴다. 닫지 않으면 오류다.
- 건너뛴 줄 수를 실행마다 출력한다.
- 원문 안의 잘못은 고치지 않는다. 표준과 어긋나는 사실은 프로젝트 용어사전에 적어 둔다.
- 화면 문구는 `<code>` · `<kbd>` · `<samp>` · `<tt>`와 `class`에 `mono` · `code`가 든 요소의 안쪽을
  같은 방식으로 제외한다. 한글이 하나라도 든 요소는 제외하지 않는다.

### 내장 검사 둘

용어사전과 무관하게 항상 실행된다.

- **조사 어긋남**(이/가 · 을/를 · 과/와): 오류. 용어사전과 규칙 팩의 대체어로 등장할 수 있는 단어 뒤에서만
  판정한다. 등재되지 않은 단어 뒤의 조사는 사람이 읽는다. 은/는은 관형형 어미와 겹쳐 검사하지 않는다.
- **같은 말이 잇달아 나옴**(`같은 같은`): 경고. 단어가 맞붙은 경우만 본다.

### 빌드가 고정값으로 바꾸는 치환자

와이어프레임 보드의 `{{b-06-new}}`처럼 빌드가 `B-06`으로 그리는 참조는 쓰는 사람이 마지막 음절을 알고
조사를 고른다. `audit.resolvedPlaceholders`에 선언하면 그려질 값으로 조사를 판정한다. 선언은 검사를
끄는 것이 아니라 켜는 것이다. 숫자 · 로마자는 한국어 읽기(0 공 · 1 일 · L 엘)로 받침을 본다.

```yaml
audit:
  resolvedPlaceholders:
    - '^([a-z])-(\d{2})(?:-[a-z0-9-]+)?$ => \U$1-$2'
```

## 쓰기 시점 훅

- 플러그인의 `hooks/hooks.json`이 `Write|Edit|MultiEdit`에 `hooks/check-md-glossary.mjs`를 건다.
  전역 · 프로젝트 `settings.json`에 선언이 없는 것이 정상이다. 차단 훅이라 오류가 있으면 편집을
  되돌리지 않고 그 시점에 멈춘다.
- 프로젝트 용어사전(`.claude/GLOSSARY.md` 또는 `GLOSSARY.md`)이 있는 프로젝트에서만 검사한다. 용어사전이
  없으면 쓰기 시점 검사가 통째로 꺼져 있다는 뜻이다.
- `Bash`로 실행한 `node` · `python` · `sed` · 히어독이 고친 문서는 훅을 지나지 않는다. 스크립트로 문서를
  고쳤으면 그 파일에 `check`를 직접 실행한다. 스크립트 명령에 `&&`로 이어 붙여 한 호출로 만든다.
- 훅이 동작하는지 의심스러우면 설정 파일을 뒤지지 말고 금지 표기를 한 줄 넣고 저장해 본다. 확인한 뒤
  그 줄을 반드시 지운다.
- `audit.localeResources`에 선언한 자원 파일에도 발동한다.

## 자원 선언 — `.claude/l10n.json`

어느 경로가 다국어 자원인지는 프로젝트가 `kinds`로 선언한다. 스킬은 기본 배치를 갖지 않는다.

- `kinds.<이름>`: `label` · `patterns`(glob) · `languages` · `format`(`json` · `properties` · `ts` ·
  `markdown` · `html` · `wireframe` · `text` · `auto`) · `register` · `exclude` · `optIn` · `stemKey`.
- `register`: `"screen"`(화면 문구, 합니다체) · `"manual"`(독자용 합니다체 설명문) · 생략(-다체 작업
  문서). 한 문체에만 뜻이 있는 검사는 이 값으로 갈린다.
- `optIn`: `true`는 기본 훑기 전부에서 뺀다. `["audit"]`처럼 명령을 적으면 그 명령에서만 뺀다. 생성기가
  다시 쓰는 부류는 번역 게이트(`audit`)에서만 빼고 문장 규칙은 그대로 둔다. `true`로 빼면 `rules` ·
  `suspects` · `grep` · `list`가 함께 그 부류를 잃고, 그 0건은 통과와 구별되지 않는다.
- `stemKey`: 파일 이름까지 번역하는 부류의 짝 맞추기. 번역되지 않는 부분을 잡는 정규식을 적는다.
  예: `"^docs/manual/[^/]+/(\\d+)-"`.
- 선언이 없어도 `rules` · `suspects` · `grep` · `list`는 `check`가 읽는 문서 집합(`.md` · `.mdx` · `.svg`)을
  대상으로 실행된다. `audit`만 선언을 요구한다.
- **`.claude/l10n.json`은 감사를 요청받았을 때만 본다.** 없으면 무엇을 검사하지 못하는지 한 줄로 말하고,
  만들라고 먼저 제안하지 않는다. 사용자가 요청하면 `check --init-l10n`으로 만들고 `list`로 파일이 실제로
  잡히는지 대조한다.

### 파일 열거의 함정

- `git ls-files`의 `**`는 경로 마디 하나 이상이라 `locales/**/ko.json`은 `locales/ko.json`에 걸리지
  않는다. 두 모양이 다 있으면 glob을 둘 적는다.
- **아직 `git add` 하지 않은 파일은 열거에 없다.** 검사되지 않은 채 0건으로 보고된다. 감사 전에 새 파일을
  스테이징하고, `list`가 세는 파일 수를 실제 파일 수와 대조한다.
- `audit.localeResources`의 glob은 저장소 루트 기준이고 `*`는 `/`를 포함하지 않는다. 하위까지 넣으려면
  `src/**/*.mjs`처럼 적는다. 아무 파일과도 맞지 않는 패턴은 `check`가 오류로 끝낸다.
- `check`는 자원 파일 수를 `자원 파일 N개 (이번 검사 범위 M개)`로 적는다. 파일 하나만 지정한 실행은 M이
  0이어도 정상이고, 선언이 깨진 것은 N이 0일 때다.

## 규칙 팩 작성

규칙마다 `id` · `scope` · `severity` · `reason` · `find` · `replace` · `hit` · `miss`를 적고
`rules --test`로 검증한다. `universal` 스코프는 항상, 도메인 스코프(`saas` 등)는 프로젝트가
`.claude/l10n.json`의 `ruleScopes`로 켤 때 적용된다. 이 저장소를 넘어 참인 규칙은 `RULES.base.json`으로,
한 프로젝트에만 참인 규칙은 그 프로젝트의 `.claude/l10n-rules.json`으로 간다.

### `\b`는 한글 뒤에서 경계가 아니다

JavaScript의 `\b`는 ASCII 기준이라 `/전에\b/`는 한국어 문장을 하나도 잡지 못하고, 그 0건은 깨끗한
저장소와 구별되지 않는다. 문구를 글자 그대로 찾거나, 경계가 필요하면 `(?<![가-힣])` · `[^가-힣]`처럼
앞뒤 글자를 직접 적는다. hit 예문을 단 규칙은 `rules --test`가 이 실패를 잡는다.

### lookahead 안에 `|$`를 쓰지 않는다

`자바(?!스크립트)`처럼 부정 lookahead로 끝나는 패턴은 문자열 끝에서 공짜로 만족한다. 코드 조각에
끊긴 마크다운 줄처럼 인위적인 끝에서는 옳은 단어가 검출된다. 고치는 곳은 패턴이 아니라 추출기다.
`segment()`가 뒤따르는 글을 `after`로 함께 싣고, 규칙은 `text + after`에 맞추되 시작 위치가 `text`
안일 때만 검출로 친다. `(?!스크립트|$)`로 적으면 진짜 끝에서도 거절하므로 미탐이 된다. 새 추출기는
`EXTRACTOR_CASES`에 `want` · `wantAfter` · `silent` · `loud`로 제 경계를 적는다.

### 조사를 경계로 삼는 규칙은 같은 음절로 끝나는 단어를 만난다

관형격 「의」를 찾는 규칙은 `회의` · `협의` · `임의` · `질의`를 「회 + 의」로 읽는다. 「가」는 추가 · 평가 ·
증가가, 「로」는 별도로 · 주로가 그렇다. `miss` 예문을 늘리는 것이 아니라 그 음절로 끝나는 단어를 통째로
빼는 조건을 건다. 규칙을 쓰기 전에 그 음절로 끝나는 단어를 세어 본다.

### 새 규칙은 다른 글에 실행한 뒤에 믿는다

`rules --test`는 지은이가 상상한 범위만 증명한다. 상상하지 못한 정상 쓰임은 hit에도 miss에도 없다.

- 그 규칙을 본 적 없는 사람이나 에이전트가 쓴 제품 문서에 실행한다. 스킬 저장소는 표본을 백틱에
  넣으므로 가장 안전한 코퍼스라 증명이 되지 않는다.
- 오탐이 나오면 그 문장을 `miss` 예문으로 올린다. `reason`에 적어 두는 것으로는 다음 사람이 패턴을
  넓히는 것을 막지 못한다.
- 좁힌 규칙의 0건은 그 유형의 넓은 형태를 `grep --regex`로 훑어 남은 것이 전부 옳은 문장인지 읽어
  증명한다.
- 오탐이 없는 규칙을 가정 하나 때문에 더 좁히지 않는다.

### 반만 판정되는 유형은 규칙이 포기하고 렌즈가 받는다

정규식이 한 유형의 절반만 가를 수 있으면, 나머지 절반에도 검출을 내는 규칙은 없는 것보다 나쁘다.
옳은 문장이 섞인 출력은 읽는 사람이 훑어 넘기게 만들고 진짜 검출까지 안 읽힌다. 글자로 구별되지 않는
구조(`다시 싣지 않는다`와 `원문을 싣지 않는다`)는 규칙에서 빼고 `lens.txt`에 어간을 둔다. 좁힐 때
`reason`에 무엇을 렌즈에 넘겼는지 적는다.

### 렌즈

규칙은 등재된 형태만 본다. 목적어를 열거할 수밖에 없고, 활용형이 음절을 바꾸며, 같은 비유가 다른
동사로 나타나므로 규칙 0건은 「깨끗하다」가 아니다. 렌즈는 반대로 넓게 짜서 사람이 읽을 후보를 뽑는다.
어간 하나를 적을 때 종결형 · 관형형 · 연결형 · 명사형을 함께 적는다. 자세한 것은
[reading-lens.md](reading-lens.md)에 있다.

```bash
K="$HOME/.claude/skills/simplecore/skills/korean-docs"
node "$K/scripts/l10n.mjs" grep --regex "$(cat "$K/references/lens.txt")"
```

### 종결형 검사는 절을 닫는 것 전부에 건다

마침표에만 앵커를 걸면 `…합니다({{ref}}).`와 `…합니다<br>`가 지나간다. 절을 닫는 것 전부(마침표 ·
여는 괄호 · 태그 · 따옴표 · 백틱 · 줄 끝)에 건다. 문체가 둘(화면은 합니다체, 작업 문서는 -다체)이면
검사도 두 방향이다.

```text
(?=[.。(<'`]|\s*$)
```

## 남이 보고한 검출을 확인한다

- 단어 금지는 `check`가, 문장 패턴은 `rules`가 낸다. 보고에는 규칙 이름만 실려 오므로 **넷을 다
  실행한다.** 다른 명령의 0건은 증거가 아니다.
- 보고 자체를 훑어서는 재현되지 않는다. 표본이 백틱에 있으면 검사기가 건너뛴다. 보고하는 쪽은 검출 줄
  원문 · 피한 문장 · 그 문장이 든 파일과 실행한 명령을 적는다. 확인하는 쪽은 그 파일을 검사하고, 파일이
  없으면 문장을 저장소 안에 넣어 스테이징한 뒤 넷을 실행한다.
- 감사가 0건이면 검사가 도달한 것인지 먼저 확인한다. 일부러 위반을 한 줄 넣어 걸리는지 본 뒤 지운다.

## SVG와 다국어 자원

- `.svg`의 `<text>` · `<tspan>` 본문은 문서와 같은 기준으로 검사한다. 태그 · 속성 · 경로 데이터는
  무시한다. 텍스트를 고치면 `svg-diagrams` 스킬로 다시 렌더해 넘침과 잘림을 확인한다. 문서 안의
  mermaid 코드 블록은 보존 대상이다.
- `audit.localeResources`에 적은 자원 파일은 따옴표 문자열의 값만 본다. 키와 주석은 검사하지 않는다.
  `--untranslated`는 적용하지 않는다. 용어사전은 검사할 파일에서 위로 올라가며 찾으므로 어느
  디렉터리에서 실행하든 같은 규칙이 적용된다.

## 전역 지침 연결

이 스킬은 모든 한국어 답변에 적용되지만 description 트리거는 평범한 질문에 걸리지 않는다. 그 간극은
전역 `~/.claude/CLAUDE.md`의 한 문단과 카드가 메운다. 사용자가 「스킬이 안 걸린다」 · 「전역 설정을 걸어
달라」고 말할 때만 안내한다.

```bash
node "$HOME/.claude/skills/simplecore/scripts/detect-simplecore.mjs" --json   # globalKorean.present · card
```

- `present`가 false: 스킬이 평범한 질문에서 걸리지 않는다. 다음 한 문단을 제안한다.
  > 세션에서 한국어 답변·산출물을 처음 작성하기 전에 `simplecore:korean-docs` 스킬의
  > `references/response-style.md`를 반드시 읽고 세션 내내 적용한다.
- `card`가 false: 가리키는 파일이 맥락에서 사라지면 기준도 사라진다.
  [global-korean-card.md](global-korean-card.md)를 요약하지 말고 표식 주석까지 통째로 붙인다.
- 전역 지침은 사용자의 파일이라 묻지 않고 고치지 않는다.
