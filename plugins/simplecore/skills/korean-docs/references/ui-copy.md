# 문장 판정 기준 — 비유·의인화·압축 (화면 문구와 문서 공통)

한국어 산출물에서 **뜻을 흐리는 문장**을 판정하는 기준. 비유, 무생물 주어, 의인화, 표어형 단정,
추상어 압축, 질문형 이름, 업무 은어를 찾아 실제 동작과 조건으로 바꾼다.

**적용 대상은 화면 문구와 문서 둘 다다.**

| 무엇 | 어디에 |
| --- | --- |
| 화면 문구 | i18n 자원·메시지 번들·메일 템플릿·와이어프레임 보드 소스, 그 문구를 만드는 화면 스크립트 |
| 문서 | 설계·기술 문서, README, 매뉴얼, 계획서, 검토 노트 — `docs/`와 작업 문서 |
| 코드 안의 설명글 | 설계 의도를 적은 주석, `OPEN:`·`TODO:` 메모 |

**Q · S · W와 「UI 요소별 문체」만 화면 문구 전용이고, 나머지 절은 문서에도 그대로 적용된다** —
그 셋은 페이지 설명·카드·라벨처럼 화면에만 있는 자리를 다룬다. 화면 전용 절에는 머리에 그 표시를 단다.

**문서에는 판정 기준이 하나, 화면 문구에는 둘이다.** 문서는 「읽는 사람이 뜻을 한 번에 이해하는가」로
충분하지만, 화면 문구는 그 위에 **「업무용 소프트웨어에서 실제로 쓰는 말인가」**를 통과해야 한다.
문법적으로 해석되는 문장과 사람이 업무 화면에서 읽는 문장은 다르다 — 「무엇에 기대는가」·「항목
하나에 딸리는 네 가지」·「목록은 사람이 손으로 채우지 않습니다」는 셋 다 문법에 맞고 셋 다 화면에
쓰지 않는다.

**목표는 문법 오류를 찾는 것이 아니다.** 영어 문장을 직역하며 생긴 비유, 무생물 주어, 의인화, 명사만
이어 붙인 문장, 불필요하게 추상적인 표현을 찾아 직접적이고 구체적인 문장으로 바꾼다.

**문법적으로 가능하다는 이유로 통과시키지 않는다.** 아래 일곱은 모두 문법에 맞지만 한국어 사용자가
쓰지 않는 문장이고, 이런 문장을 만나면 **단어 몇 개만 바꾸지 말고 전달하려는 사실을 확인해 문장
전체를 다시 쓴다.**

- 무엇에 기대는가 / 아무것도 기대지 않습니다 / 장비가 제대로 작동하는지에 기댑니다
- 항목 하나에 딸리는 네 가지 / 이 결과에서 나오는 네 가지 의무
- 설정 하나가 무엇을 켜는가 / 목록은 사람이 손으로 채우지 않습니다

**전수로 검토·수정하는 작업**은 이 기준에 더해 [ui-copy-sweep.md](ui-copy-sweep.md)의 절차를
따른다 — 어떤 순서로 읽고, 무엇을 단위로 대조하고, 무엇을 끝으로 보는지가 거기 있다. 어휘·표기는
[response-style.md](response-style.md), 번역투 카탈로그는 [korean-style.md](korean-style.md)가
원본이다.

# 판정 관점

아래는 검색어 목록이 아니라 검토 관점이다. **목록에 없는 비슷한 문장도 전부 찾는다.**

## 세 가지를 갈라서 판단한다

| 무엇 | 어떻게 |
| --- | --- |
| 법정 용어·정식 기술 용어 | 그대로 둔다. 어색하다는 이유로 쉬운 말로 바꾸면 법적·기술적 의미가 달라진다 |
| 그 용어가 든 문장의 조사·어순·서술어 | 자연스럽게 다시 쓴다 |
| 실제 물리 동작 | 비유가 아니므로 그대로 둔다. 출입문이 실제로 열리고, 잠금 장치를 실제로 잠근다 |

**명칭 보존이 비유 보존은 아니다.** 도메인 모델이나 내부 API의 이름이 `gate`이더라도, 사용자 문구와
설계 노트에서는 그 이름이 아니라 실제 의미를 쓴다 — 필수 요건 · 배정 전 요건 확인 · 접근 조건 판정 ·
단계 진행 조건. 명칭을 남길지 여부와 무관하게, 주위의 서술어는 언제나 실제 처리 내용으로 바꾼다.

**정식 기술 용어가 든 문장도 일반 사용자가 기능을 추론해야 한다면 다시 쓴다.** 명칭과 실제
효과를 함께 적는다.

- 배치 관문이 잡습니다 → 배치 전 미충족 요건을 판정해 배정을 제한합니다
- 정책이 집행됩니다 → 해당 정책을 판정에 적용합니다
- 스코프로 가릅니다 → 접근 범위에 따라 조회 권한을 구분합니다
- 규칙에 걸립니다 → 규칙의 대상 조건을 충족해 대기열에 등록됩니다
- 렌더링이 막힙니다 → 렌더링이 완료될 때까지 제출을 제한합니다

## A. 물리 비유 → 기능 동사

**비유를 다른 비유로 바꾸지 않는다.** 문장을 매끄럽게 다듬는 것이 아니라, 전달하려는 사실을 확인해
다시 쓴다. 다시 쓰기 전에 여섯 가지에 답한다 — 실제 주체는 무엇인가 · 시스템이 실제로 하는 동작은
무엇인가 · 적용 대상은 무엇인가 · 어떤 조건에서 하는가 · 결과는 무엇인가 · 사용자가 지금 알아야
하거나 해야 하는 것은 무엇인가.

서술어는 기능을 있는 그대로 가리키는 말을 고른다 — 적용·포함·등록·저장·전송·동기화·표시·구분·
확인·선택·제출·승인·제한·차단·완료·취소·복구·충족·발생·유지·조회·변경·삭제. **범위가 넓은
동사(처리·진행·관리)도 남용하지 않는다**: 화면에서 더 정확한 동작을 알 수 있으면 검토·승인·서명·
배포·전송·폐기로 좁힌다.

| 비유 | 확인할 것 | 대체 |
| --- | --- | --- |
| 조건·기능이 무엇에 **기대다 · 의지하다** | 선행 조건인가 운영 조건인가 | ~해야 한다, 유지 조건, 추가 조건이 없다 |
| 정책·의무가 **걸리다 · 붙다 · 딸리다** | 적용인가 차단인가 경고인가 | ~에 적용된다, ~에 포함된다 |
| 결과·의무·경고가 **나오다 · 따라오다 · 올라오다** | 생성인가 적용인가 | 판정 결과에 따라 ~가 적용된다 |
| 보고서·팩이 값을 **싣다 · 안고 오다 · 데려오다** | 포함인가 첨부인가 전송인가 | ~에 해당 값을 포함한다, ~를 공급한다 |
| 화면·카드·목록이 정보를 **쥐다 · 품다 · 말하다** | 표시인가 상태 관리인가 | ~에 표시한다 |
| 작업·단계·흐름이 **막히다 · 풀리다 · 열리다 · 닫히다** | 권한인가 선행 업무인가 오류인가 | 진행할 수 없다, 진행할 수 있다 |
| 기준·조건·관계가 **무너지다 · 살아나다 · 버티다** | 미충족인가 해제인가 복구인가 | 충족하지 않는다, 다시 표시된다 |
| 숫자·경고·상태가 **오르다 · 내리다** | 증가인가 변경인가 | 늘어난다, ~로 변경한다 |
| 기록이 서버로 **올라가다**, 단말로 **내려오다** | 전송인가 저장 완료인가 | 서버로 전송한다, 기기에 내려받는다 |
| 일정·기한이 **밀리다**, 업무가 뒤로 **넘어가다** | 연기인가 재배정인가 | 연기될 수 있다, 다음 담당자에게 자동 배정된다 |
| 화면·정책이 어디에 **서다**, 사용자가 그 위를 **딛다** | 표시인가 적용 기준인가 | ~에 표시된다, ~를 기준으로 판정한다 |
| 여러 대상이 서로 **물리다**, 업무가 다른 업무를 **물고 있다** | 선후 관계인가 단순 연계인가 | 두 업무에 선후 관계가 있다 |
| 내용을 화면에 **펼치다**, 카드 **뒤에 두다** | 표시인가 도움말 제공인가 | ~를 함께 표시한다, 도움말에서 확인할 수 있다 |
| 기준이 대상을 **가르다**, 결과에 따라 대상이 **갈리다** | 분류인가 제외인가 제한인가 | 해당 기준에 따라 대상을 구분한다 |
| 기한·주기를 **시계**라 부르기 | 어느 기한인가 | 신고 기한, 처리기한 |
| 담당자를 **주인**이라 부르기 | 담당자인가 작성 주체인가 | 담당자, 작성 주체, 잠근 사람 |
| 단계를 **걸음**이라 부르기 | 절차인가 순서인가 | 단계, 순서 |
| 화면이 하는 일을 **동사·첫 질문**이라 부르기 | 무엇을 하는 화면인가 | 이 화면에서 하는 일은 ~다 |
| 설정·예약·판정을 **잡다** | 설정인가 예약인가 판정인가 | 설정한다, 예약한다, 판정한다 |
| 자격·기능 키·사건이 무엇을 **열다** | 허용인가 시작인가 | ~로 사용할 수 있다, ~에서 시작된다 |
| 등록·전송·상신을 **올라오다·올라가다** | 등록인가 전송인가 상신인가 | 등록된다, 전송된다, 요청된다 |
| 예외·관계를 **깨지다·얽힘·갈림선** | 예외인가 연결인가 기준인가 | 예외가 있다, 연결 관계, 구분 기준 |

## B. 「닿다」와 「길」

**정보나 기능이 사람·서버·외부 시스템·출입문·문서에 「닿는다」고 쓰지 않는다.** 「닿다」는 실제
접촉을 가리키는 동사여서 알림 전달·서버 전송·시스템 연결·정책 적용·화면 접근을 대신하면 실제 동작이
사라진다.

- 알림이 사용자에게 닿지 않습니다 → 사용자가 알림을 수신하지 못했습니다
- 특정 메신저를 쓰는 사용자에게 닿는 길이 없습니다 → 그 메신저를 쓰는 사용자에게 알림을 보낼 수 있는 채널이 없습니다
- 서버에 닿은 뒤 → 서버 전송이 완료된 뒤
- 외부 타임스탬프에 닿지 못했습니다 → 외부 타임스탬프 서버에 연결할 수 없습니다
- 판정이 장치 제어에 닿지 않습니다 → 판정 결과가 장치 제어에 적용되지 않습니다
- 승인된 변경이 자료에 닿지 않았습니다 → 승인된 변경이 자료에 반영되지 않았습니다
- 화면에 닿을 길이 없습니다 → 해당 화면에 접근할 수 없습니다
- 긴급 알림이 실제로 닿는 곳 → 긴급 알림 수신 채널
- 이 채널이 닿는 대상 → 이 채널의 수신 대상
- 보존 기록에 닿는 길 → 보존 기록의 조회·내보내기 기능

**「길」도 함께 구체화한다** — 알림을 보내는 길 → 알림 채널 / 화면으로 가는 길 → 화면 접근 권한
또는 이동 경로 / 사람이 하는 길 → 수동 처리 방법 / 이의 제기할 길 → 이의 제기 방법.

바늘이 손가락에 닿거나 부품이 바닥에 닿는 것처럼 실제 접촉은 그대로 둔다. 수치가 한계에
이르는 것은 「한도에 닿는다」가 아니라 **「한도에 도달한다」**로 쓴다.

## C. 대체 처리 순서를 「사다리」로 부르지 않는다

알림 전송 실패 후 다른 채널로 넘어가는 절차, 승인 실패 후 담당자를 바꾸는 절차처럼 순서가 정해진
처리를 이동 비유로 설명하면 **무엇이 자동이고 어디서 사람이 개입하며 마지막 실패 상태가 무엇인지가
숨는다.**

- 대체발송 사다리 → 대체발송 순서, 대체 채널 우선순위
- 메신저 발송이 실패하면 문자로 갑니다 → 메신저 발송에 실패하면 문자로 자동 전송합니다
- 사다리의 끝은 문자입니다 → 자동 대체발송의 마지막 채널은 문자입니다
- 끝에서 실패하면 사람이 전화합니다 → 문자 전송에도 실패하면 담당자가 전화합니다
- 다음 담당자에게 넘어갑니다 → 다음 담당자에게 자동 배정됩니다
- 실패 건이 수동 처리로 넘어갑니다 → 실패 건을 수동 처리 대기열에 등록합니다

단계 전환 자체는 「다음 단계로 진행합니다」로 쓸 수 있다. 실제 동작이 전송·배정·등록·승인·보류이면
그 동사를 직접 쓴다.

## D. 상태·적용·기간을 방향·스위치·이동으로 말하지 않는다

모드·권한·제한·동기화 상태, 기능 적용 여부, 보존기간을 물리적 방향이나 전원 상태나 이동으로만
설명하지 않는다. 실제 상태, 적용 대상, 허용 여부, 처리 결과를 직접 쓴다.

- 집행 모드로 올린다 / 참조 모드로 내린다 → 집행 모드로 변경한다 / 참조 모드로 변경한다
- 기능이 열린다 → 해당 기능을 사용할 수 있다
- 화면이 잠긴다 → 설정을 변경할 수 없다
- 규칙이 꺼진다 → 규칙이 비활성화된다
- 되살아나면 다시 보낸다 → 다시 활성화하면 대기 건을 재전송한다
- 장비가 살아난다 → 장비가 재가동된다
- 이 기능은 기업 요금제에서 켜집니다 → 이 기능은 기업 요금제에 적용됩니다
- 본인 확인 항목은 대리가 막힙니다 → 본인 확인 항목은 대리로 작성할 수 없습니다
- 연결이 열리면 소급합니다 → 외부 연결이 복구되면 미처리 기록에 소급 적용합니다
- 기록 하나가 왜 10년을 가는가 → 거래 기록을 10년 보존하는 이유

**「켜기」·「끄기」는 사용자가 활성화 여부를 직접 바꾸는 스위치의 동작명일 때만 쓴다.** 측정값·
법령·정책·고객 유형이 기능을 자동으로 적용하거나 대상을 판정하는 자리는 적용됩니다·대상으로
판정합니다·활성화됩니다다. **버튼 이름이 「켜기」·「끄기」로 정해져 있어도 설명 문장에서는**
활성화·비활성화·사용·중지처럼 결과 상태를 함께 적는다.

## E. 업무 은어와 구어적 이동 동사

업무 현장에서 관행으로 쓰더라도 법적·행정적 상태가 불명확한 업무 은어는 화면 문구에 쓰지 않는다.
특히 **나가다·올라오다·내려오다·걸다·풀다·붙이다로 승인·발급·제출·등록·적용을 대신하지 않는다.**

- 허가가 나갑니다 → 이용 허가가 발급됩니다
- 결재가 올라갑니다 → 결재가 요청됩니다
- 증명서가 올라온 뒤 → 증명서가 등록된 뒤
- 자료가 내려옵니다 → 자료를 기기에 내려받습니다
- 보완 대책을 겁니다 → 보완 대책을 적용합니다
- 조건과 기한을 붙입니다 → 조건과 이행 기한을 지정합니다
- 제한을 풉니다 → 제한을 해제합니다

상태값이나 이벤트 이름이 `issued`·`uploaded`·`downloaded`이더라도 **사용자 문구에서는 한국어
행정 동작을 정확하게 쓴다.**

## F. 「통째로 · 조용히 · 그대로」로 영향을 뭉뚱그리지 않는다

변경 범위와 결과를 부사 하나로 덮지 않는다. 바뀌는 항목, 유지되는 항목, 사용자에게 알리는 방식을
적는다.

- 일정이 통째로 밀립니다 → 설치 일정이 연기될 수 있습니다
- 기록이 통째로 빕니다 → 해당 시간대의 접속 기록이 누락됩니다
- 이 묶음을 통째로 되돌립니다 → 해당 회차에 포함된 모든 항목을 되돌립니다
- 문이 조용히 남습니다 → 연결되지 않은 장치를 결과 목록에 표시합니다
- 자격이 그대로 따라갑니다 → 기존 이력과 자격 정보를 유지합니다

## G. 무생물 주어와 의인화

화면·카드·목록·정책·규칙·보고서·결과·일정·버튼이 사람처럼 판단하거나 말하거나 기억하거나 책임지는
문장을 쓰지 않는다. **「화면의 몫이다」·「화면이 답한다」·「화면이 밝힌다」·「목록이 보여 준다」도
같다.**

| 금지 | 대체 |
| --- | --- |
| 화면이 사용자에게 다음 행동을 말합니다 | 화면에 다음 작업을 안내합니다 |
| 이 카드가 모든 값을 기억합니다 | 카드에 모든 값을 표시합니다 |
| 정책이 작업을 막습니다 | 해당 정책이 적용되면 작업을 진행할 수 없습니다 |
| 결과가 네 가지 의무를 가져옵니다 | 판정 결과에 따라 네 가지 의무가 적용됩니다 |
| 보고서가 근거를 안고 들어옵니다 | 보고서에 판단 근거를 포함합니다 |
| 그 사실을 화면이 밝힙니다 | 화면에 해당 사실을 안내합니다 |
| 임박한 것을 미리 보이는 일이 이 화면의 몫입니다 | 점검 임박 장비를 미리 표시합니다 |
| 이 화면이 답하는 유일한 질문입니다 | 이 화면에서 해당 상태를 우선 확인합니다 |
| 화면이 답해야 하는 것은 어디로 가느냐입니다 | 집결 장소를 가장 먼저 안내합니다 |
| 설정 화면이 답합니다 | 설정 화면에서 변경 방법을 안내합니다 |

**「보이다」도 무조건 쓰지 않는다.** 시스템이 표시하는 것인지 사용자가 조회하는 것인지를 갈라
표시한다·안내한다·조회할 수 있다·확인한다 가운데 고른다.

**주체와 서술어의 호응은 문법뿐 아니라 의미로도 본다** — 「값이 정책을 수행한다」·「결과가 의무를
실행한다」·「일정이 작업자를 완료한다」·「카드가 문서를 승인한다」는 문법 오류가 아니라 주체가 틀린
문장이다. 시스템·관리자·담당자·승인자·정책·상태·데이터 가운데 실제 주체를 확인해 고친다.

## H. 명사와 명사의 관계를 비유로 감추지 않는다

「A에 붙는 B」·「A에 딸리는 B」·「A가 켜는 B」·「A 뒤에 있는 B」는 관계의 성격을 읽는 사람이
짐작하게 만든다. 관계를 확인해 이름을 붙인다.

| 관계 | 표현 |
| --- | --- |
| 적용 | A에 적용되는 B |
| 포함 | A에 포함된 B |
| 소속 | A에 속한 B |
| 생성 | A를 기준으로 생성된 B |
| 선행 | B를 시작하기 전에 완료해야 하는 A |
| 참조 | A가 참조하는 B |
| 연계 | A와 연계된 B |
| 조건 | A일 때 필요한 B |

## I. 조직·역할·기능을 모두 「자리」라고 부르지 않는다

「자리」는 실제 장소·좌석·화면 요소의 배치 위치를 뜻할 때만 쓴다. 조직·직위·필수 역할·접근 수단·
화면·입력란·기능의 목적을 모두 「자리」로 부르면 대상을 문맥으로 추측해야 한다.

- 사람이 소속되는 자리 → 사용자가 소속되는 조직
- 사람이 아닌 것이 접근하는 자리 → 시스템 연동에 사용하는 서비스 계정 관리 화면
- 검토자 자리가 비어 있습니다 → 필수 역할인 검토자가 지정되지 않았습니다
- 이 화면이 값을 받는 자리입니다 → 이 화면에서 값을 입력합니다
- 바깥 시스템과 잇는 자리 → 외부 시스템 연동 설정
- 의무가 걸리는 자리 → 그 의무를 이행하는 조직
- 사람이 아니라 자리입니다 → 특정 개인이 아니라 작업별 필수 역할을 지정합니다
- 사람이 하는 길이 열려 있는 자리 → 같은 업무를 수동으로 처리할 수 있습니다

「같은 위치에서 반복 발생」·「버튼을 같은 자리에 표시」·「주민등록번호 앞 7자리」·「빈 좌석」처럼
실제 공간·배치·자릿수를 뜻하는 표현은 그대로 둔다.

**이름 자리의 「자리」는 화면 이름을 다 고친 뒤에도 남는다.** 표 머리글의 「찾은 자리」·「어긋난
자리」, 필드 라벨의 「자리 이름」, 통계 타일의 「빈 자리」는 값에 가려 눈에 띄지 않는다 — 무엇을
가리키는지로 갈라 쓴다: 위치 · 항목 · 화면 · 직책 · 미편성. **법정 직위나 정식 역할은 「자리」로 풀지 않고
해당 용어를 그대로 쓴다.**

## J. 모호한 주어와 지시어

`이것`·`그것`·`이 결과`·`이 값`·`해당 건`·`이 경우`가 무엇을 가리키는지 한 번에 알 수
없으면 명칭을 다시 적는다. 같은 화면에 대상이 여럿이면 지시어를 쓰지 않는다.

- 이 결과에서 나오는 네 가지 의무 → 심사 결과에 따라 적용되는 네 가지 의무
- 이것이 완료되면 다음으로 넘어갑니다 → 사전 심사가 승인되면 이용 신청서를 작성할 수 있습니다

## K. 영어식 부정문과 수동 표현

영어 원문의 구조를 유지한 부정문·이중 부정·불필요한 피동을 찾는다.

- 목록은 사람이 손으로 채우지 않습니다 → 시스템이 목록을 자동으로 생성합니다
- 이 값은 사용자에 의해 변경될 수 없습니다 → 사용자는 이 값을 변경할 수 없습니다
- 승인 없이는 진행되지 않도록 되어 있습니다 → 승인을 완료해야 다음 단계를 진행할 수 있습니다

행위 주체가 중요하지 않거나 법령 문장에서 피동이 정착한 자리는 억지로 능동으로 바꾸지 않는다.

## L. 일괄 치환이 남긴 조사·어미·호응을 따로 검사한다

**앞의 수정이 만든 오류는 원문에 없던 것이라 눈에 띄지 않는다.** 낱말을 바꾸면 뒤따르는 조사가
어긋나고, 문장을 다시 쓰면 어미가 섞인다. 고친 뒤에 이 아홉을 따로 훑는다.

| 무엇 | 예 |
| --- | --- |
| 을/를 · 이/가 · 은/는 · 으로/로 · 와/과 | 「교육 발생 조건」**는** → 「교육 발생 조건」**은** |
| 앞말과 맞지 않는 단수·복수 | 항목**들이** 각각 → 항목이 각각 |
| 높임말과 해라체가 한 자리에 섞임 | 「등록합니다」와 「등록한다」가 한 화면에 |
| 「할 수 있습니다」와 「가능합니다」의 중복 | 조회 가능합니다 → 조회할 수 있습니다 |
| 같은 낱말의 연속 | 기록 기록을 → 기록을 |
| 두 칸 이상의 공백 | 확인  합니다 → 확인합니다 |
| 괄호 앞뒤와 숫자·단위의 띄어쓰기 불일치 | 30일(기한) / 30 일 (기한) 가운데 하나로 |
| 제목과 설명이 서로 다른 대상명을 씀 | 제목 「작업허가」 · 설명 「허가서」 |
| 버튼은 명령형인데 설명이 장황함 | 버튼 「등록」 · 설명 세 문장 |

**조사 어긋남과 같은 말의 연속은 감사 스크립트가 잡는다** — 사람은 나머지 일곱을 본다. 특히
**높임말·해라체 혼용과 제목·설명의 대상명 불일치는 한 파일 안을 세로로 읽어야** 드러난다.

## M. 제목은 질문이 아니라 이름이다

설명 문구나 도움말 제목을 「무엇을 하는가」·「무엇에 기대는가」·「무엇을 켜는가」·「어떻게
흐르는가」로 쓰지 않는다. 사용자가 찾는 정보를 명사형 제목으로 바꾼다.

- 무엇에 기대는가 → 효과 유지 조건
- 항목 하나가 무엇을 켜는가 → 항목별 적용 요건
- 이 화면이 무엇을 쥐고 있는가 → 화면에 표시되는 정보
- 기록은 어디로 올라가는가 → 기록 전송 위치
- 누가 이 단계를 여는가 → 다음 단계 진행 조건

**다이얼로그·도움말 카드·표 제목·차트 제목도 같다.** 「무엇이 다른가」·「왜 필요한가」·「어떻게
되는가」·「누가 정하는가」는 영어 문서의 설명 섹션 제목을 직역한 것이고, 제목만으로 내용을 예측할
수 없어 사용자가 답을 얻으려면 본문을 다 읽어야 한다. **제목에는 다루는 대상과 정보 유형을 쓴다.**

- 한 제출 기록은 무엇으로 이루어지는가 → 제출 기록의 구성과 변경 가능 여부
- 무엇이 반드시 남는가 → 필수 감사 로그 항목
- 기한의 세 가지 모양 → 법정 제출기한 유형과 표시 방식
- 개정은 무엇을 바꾸고 무엇을 바꾸지 않는가 → 법규 개정의 적용 범위와 기존 기록 보존
- 회의체마다 무엇이 다른가 → 회의체별 구성과 의결 요건
- 등급마다 무엇을 믿을 수 있는가 → 외부 자격 확인 방법별 검증 수준

질문형 제목은 **실제 사용자의 질문을 인용하는 상담·검색 화면**에서만 쓴다. 도움말 카드·참조
다이얼로그·표 제목·차트 제목처럼 내용을 분류하는 자리는 명사형 정보 구조를 쓴다.

**제목이 질문이면 명사형으로 바꾸는 것이 기본이고, 남길 수 있는 것은 사용자가 실제로 입 밖에 내어
묻는 형태뿐이다** — 「누가 승인할 수 있나요?」·「제출 후에도 수정할 수 있나요?」. 「~는가」로 끝나는
제목은 사용자의 질문이 아니라 **설계자가 스스로에게 던진 질문**인 경우가 대부분이고, 그것은 제목이
아니라 그 화면이 답해야 할 내용이다. 서술어가 비유이면(「무엇을 켜는가」·「어디로 올라가는가」)
질문 형식과 비유를 함께 지운다.

**질문형은 화면 이름보다 필드 라벨과 표 머리글에 더 오래 남는다.** 이름은 눈에 띄지만 라벨은 값에
가려 지나치기 쉬워, 한 제품에서 화면 이름을 다 고친 뒤에도 라벨에만 아흔일곱 개가 남아 있었다.
라벨은 값의 종류를 이름으로 적는 자리다 — 무엇을 뜻하는가 → 의미, 끌 수 있는가 → 비활성화 가능
여부, 왜 위험한가 → 위험 요인, 어떻게 들어오는가 → 입력 경로, 누가 지정하는가 → 지정 주체.
**어미를 「~는가」로만 찾으면 「필요한가」·「중대한가」·「어려운가」가 빠져나간다.**

**명사만 이어 붙인 제목도 관계를 짐작하게 만든다.**

- 대상 결과 의무 적용 상태 → 판정 결과에 따른 의무 적용 현황
- 세션 단계 미완료 항목 구분 → 세션 단계별 미완료 항목
- 정책 경고 세 가지 경우 → 정책 경고가 발생하는 세 가지 경우

제목은 짧아야 하지만 조사 하나를 생략해 뜻이 흐려지면 조사나 관형어를 넣는다.

## N. 과장·단정·감정 평가로 기능을 설명하지 않는다

「최악이다」·「가장 위험하다」·「아무도 진지하게 하지 않는다」·「유일한 길이다」처럼 근거 없이
단정하거나 감정을 유도하는 문장을 쓰지 않는다. 위험과 우선순위는 실제 조건과 결과로 설명한다.

- 일곱 번째는 사고가 됩니다 → 같은 원인이 실제 장애로 이어질 수 있습니다
- 이 기록이 최악입니다 → 필수 요건 미충족 상태의 처리 기록을 별도로 확인합니다
- 외부 기관 일정이 유일한 길입니다 → 지정된 외부 기관의 일정을 예약해야 합니다

법령이나 확정된 정책에 따라 방법이 하나뿐이면 「해야 합니다」·「할 수 없습니다」로 요건을 직접 쓴다.

## O. 「가능 · 급한 · 즉시」는 기준과 함께 쓴다

「수정 가능」·「급한 알림」·「즉시 반영」처럼 짧은 상태 표현만 두지 않는다. 같은 「수정 가능」이라도
다음 발송부터 적용되는지, 외부 심사를 거쳐야 하는지, 이전 문안이 계속 나가는지가 다르다.

- 수정 가능이 채널마다 다른 뜻입니다 → 채널마다 변경 문안의 적용 시점이 다릅니다
- 저장하면 바로 반영됩니다 → 저장한 문안은 다음 발송부터 적용됩니다
- 문안을 수정할 수 있습니다 → 문안을 변경할 수 있지만 재심사를 통과한 뒤 발송에 적용됩니다
- 급히 고쳐야 하는 알림 → 상황에 따라 문안을 즉시 변경해야 하는 긴급 알림

시간 기준이 있으면 「다음 발송부터」·「승인 완료 후」·「발령 즉시」·「5분 이내」처럼 적용 시점이나
제한 시간을 명시한다. **정해지지 않았으면 숫자를 지어내지 말고 처리 조건을 분명히 적는다.**

## P. 페이지 설명의 「간접의문절 + 입니다」

페이지 제목 아래 설명에서 **「~인지입니다」·「~한지입니다」·「~할지입니다」·「~될지입니다」·
「~볼지입니다」처럼 간접의문절에 「입니다」를 붙이지 않는다.** 영어 `This page is about whether…`
구조를 한국어 어순으로만 옮긴 번역체이고, 의문절을 명사 서술어처럼 끝내므로 문법으로는 해석돼도
한국어 문장으로는 서지 않는다.

- 누구에게 무엇이 나갔고 언제까지 유효한지입니다 → 사용자별 지급 내역과 유효기간을 확인합니다
- 어느 상표로 보일지입니다 → 콘솔·앱·출력물에 표시할 상표를 설정합니다
- 누구를 누구로 볼지입니다 → 외부 시스템 연결과 신원 매핑을 설정합니다
- 지금도 검증되는지, 언제까지 검증될지입니다 → 현재 검증 상태와 검증 가능 기간을 확인합니다

**「가지입니다」·「기한입니다」·「별지입니다」처럼 완성된 명사로 끝나는 문장까지 마지막 글자만 보고
고치지 않는다.** 「~는지 확인합니다」는 문법적으로 자연스러울 수 있으나, 페이지 설명에서 같은 구조가
반복되거나 대상이 「무엇」·「누가」·「어느 것」처럼 모호하면 구체적인 항목명과 확인합니다·관리합니다·
설정합니다·표시합니다를 쓴다.

## Q. 페이지 설명은 대상과 기능을 직접 쓴다

> 화면 문구 전용 — 문서에는 이 자리가 없다.

**페이지 설명은 제목을 다시 푸는 수수께끼나 질문이 아니다.** 그 화면에서 사용자가 확인하거나
처리하는 대상을 한 문장만 읽어도 알 수 있어야 한다. 「무엇이 언제 끝나는지 봅니다」·「누가 무엇을
했는지 봅니다」·「이 화면에서 무엇이 나옵니다」처럼 의문사와 포괄어에 기대지 않는다.

- 무엇이 언제 끝나고 무엇이 이미 지났는지 봅니다 → 계약별 만료 시각과 만료 상태를 확인합니다
- 누가 언제 막히는지 봅니다 → 미이수로 이용이 제한되는 사용자와 제한 시점을 확인합니다
- 무엇이 켜져 있고 무엇이 왜 꺼져 있는지 봅니다 → 기능별 활성화 상태와 비활성화 사유를 확인합니다
- 무엇을 언제 어디에 냈는지 봅니다 → 기관별 제출 내역과 남은 제출 기한을 확인합니다

설명은 **대상 → 기준·범위 → 기능** 순서를 우선한다.

| 자리 | 무엇을 적나 |
| --- | --- |
| 대상 | 이용 허가·법정 의무·수신자·보존 기록처럼 화면이 다루는 구체적인 명칭 |
| 기준·범위 | 사용자별·채널별·법령별·현재·만료 후처럼 판단에 필요한 범위 |
| 기능 | 확인합니다·관리합니다·설정합니다·기록합니다·발급합니다·전송합니다 |

**상세 화면이 대상명·일시·상태를 「A동 3층 · 2026-08-12 · 진행 중」처럼 짧게 나열하는 것은
허용한다** — 이 자리는 설명문이 아니므로 문장으로 억지로 늘리지 않는다. 반대로 기능 설명을 쓸
때는 `여기`·`그것`·`무엇`·`누가`·`저쪽`·`이쪽`만으로 대상을 대신하지 않는다.

## R. 내부 노트와 강조 제목도 비유 없이 쓴다

`OPEN:`·`TODO:`·설계 메모·보드 주석처럼 최종 사용자에게 바로 노출되지 않는 문구도 검토 대상이다.
**이런 문구는 나중에 화면 카피나 요구사항의 원문이 되므로** 조사와 종결어미를 생략하지 않는다.

- 근거 조문은 확인 필요다 → 근거 조문을 확인해야 한다
- 값으로 그리지 않는다 → 화면에 확정값으로 표시하지 않는다
- 어느 셋인지 확인 필요 → 해당하는 세 항목을 확인해야 한다

미확정 사실을 확정된 것처럼 다듬지는 않는다. 「확인 필요」·「검토 중」·「근거 조문 확인 전」이라는
상태는 유지하되 완전한 문장으로 쓴다.

**노트라는 이유로 짧고 인상적인 문장, 영어식 비유, 의인화된 강조 제목을 허용하지 않는다.** 특히
`<strong>` 안의 문장은 맥락을 압축하려다 비유가 되기 쉬우므로 실제 설계 결정과 이유를 직접 쓴다.

- 권한과 책임이 겹치는 자리다 → 항목별로 두 담당자의 권한을 구분합니다
- 점검 결과가 프로그램을 켠다 → 점검 결과에 따라 항목별 프로그램 대상이 정해집니다
- 겹침 시간대가 인계의 자리다 → 인계는 두 교대조가 함께 근무하는 시간에 실시합니다
- 한 게시물을 읽는 자리는 하나다 → 게시물 상세 정보는 하나의 패널에 표시합니다
- 담당은 사람이 아니라 자리로 정한다 → 점검 담당자는 개인이 아니라 직책으로 지정합니다
- 사건마다 시계가 흐른다 → 사건마다 처리기한이 다릅니다

노트의 강조 제목은 다섯 가지 가운데 하나를 분명히 설명해야 한다.

1. 어떤 설계 결정을 했는가
2. 어떤 조건에서 적용되는가
3. 누가 어떤 권한을 가지는가
4. 어떤 법적·업무상 이유가 있는가
5. 어떤 화면이나 데이터와 연결되는가

**강조 제목을 지워도 뜻이 달라지지 않는 수사적 문장이면 구체적인 설계 결정으로 다시 쓴다.** 실제
화면 위치를 뜻하는 「표의 첫 번째 열」·「버튼 아래」·「주민등록번호 앞 7자리」는 비유가 아니므로
유지한다.

## S. 카드와 다이얼로그 설명에서 추상 명사와 압축 비유를 없앤다

> 화면 문구 전용 — 문서에는 이 자리가 없다.

카드와 다이얼로그는 짧아야 하지만, **짧게 쓰려고 「본문」·「전제」·「갈래」·「모양」·「묶음」·
「무게」·「흐름」 같은 추상어로 의미를 압축하지 않는다.** 데이터나 기능을 이동하는 사물로 표현하는
것도 같다 — 「CAPA로 갑니다」·「화면이 열립니다」·「기한이 흐릅니다」·「배지가 붙습니다」.

- 대피 시간과 실패 지점이 평가의 본문입니다 → 대피 완료 시간과 계획대로 수행하지 못한 지점을 기록해 훈련 결과를 평가합니다
- 거기서 나온 것이 CAPA로 갑니다 → 확인된 미흡 사항은 CAPA로 등록해 개선 여부를 추적합니다
- 원본을 고치지 않는 것이 증거력의 전제입니다 → 제출 원본은 수정하지 않고 정정 기록을 추가합니다
- 요청은 다섯 갈래입니다 → 요청을 열람, 정정·삭제, 처리정지 등 유형별로 구분합니다
- 묶음은 제품 없이 열려야 합니다 → 증빙은 별도 계정이나 프로그램 없이 확인할 수 있는 파일 형식으로 제공합니다
- 만료 기한은 계속 흐릅니다 → 가동을 중지해도 검사 유효기간은 변경되지 않습니다

설명 문장은 네 단계로 쓴다.

1. 대상이나 조건을 구체적으로 밝힌다
2. 시스템 또는 사용자가 수행하는 실제 동작을 쓴다
3. 허용·제한·보존·전송·등록 등 처리 결과를 명시한다
4. 필요할 때만 법적·업무상 이유를 한 문장으로 덧붙인다

**한 문장에 서로 다른 판단이 셋 이상 들어가면 문장을 나눈다.** 가운데점과 대시로 단편을 이어 붙인
힌트도 같은 기준으로 보고, 「대상 · 기준 · 결과」처럼 병렬 구조가 분명할 때만 유지한다.

## T. 조건·판정·제한을 문이나 관문에 빗대지 않는다

영어 `gate`·`open`·`close`·`block`을 그대로 옮긴 「관문」·「문을 연다」·「문을 막는다」·「닫힌다」는
실제 업무 조건과 시스템 동작을 감춘다. 사용자는 비유를 해석한 뒤에야 배정이 제한되는지, 접근이
거부되는지, 다음 단계를 진행할 수 없는지 알 수 있다. **대상과 처리 결과를 직접 쓴다.**

- 자격이 관문을 연다 → 자격별로 배정·승인 시 확인할 단계를 지정합니다
- 만료가 관문을 닫는다 → 유효기간이 지나면 해당 작업의 배정을 제한합니다
- 법정 관문은 끌 수 없다 → 법정 필수 요건은 비활성화할 수 없습니다
- 사람이 관문에 걸렸다 → 사용자가 배정 요건을 충족하지 못했습니다
- 관문이 샌다 → 필수 요건 판정이 누락됐다
- 관문을 넘긴다 → 개인별 예외를 승인한다
- 관문이 사람을 막는다 → 미충족 요건으로 해당 사용자의 배정을 제한한다
- 관문이 무엇을 막는가 → 미충족 시 제한되는 작업
- 실제로 문을 막는 상태다 → 판정 결과를 통제 시스템에 전달해 접근을 제한하는 상태입니다
- 승인되지 않아 착수가 막힌다 → 승인되기 전에는 착수할 수 없습니다

**「출입문」·「문 개방」·「문 잠금」처럼 실제 물리 설비와 동작을 가리키면 그대로 쓴다.** 내부 API나
도메인 모델의 고유 명칭이 `gate`이더라도 사용자 문구와 설계 노트에서는 실제 의미에 따라 「필수
요건」·「배정 전 요건 확인」·「접근 조건 판정」·「단계 진행 조건」으로 푼다.

## U. 표어형 단정문을 업무 절차 설명으로 바꾼다

**「A가 곧 B다」·「A는 B일 뿐이다」·「A가 유일한 방어다」·「A가 핵심이다」·「A가 아니라 B다」처럼
짧고 강하게 단정하는 문장을 쓰지 않는다.** 인상은 강하지만 실제 조건·처리 방법·확인 주체를
생략하므로 사용자가 기능을 정확히 이해하기 어렵다. 영어 문서의 슬로건이나 대조형 문장을 직역한
경우가 많고, 법적·업무상 효과를 필요 이상으로 과장하기도 한다.

- 사진이 곧 근거다 → 이상 항목에는 상태를 확인할 수 있는 사진을 첨부해야 합니다
- QR이 유일한 방어입니다 → QR 조회로 이미 인쇄된 증명서의 현재 유효 여부를 확인할 수 있습니다
- 게시 위치가 증빙이다 → 게시 위치, 게시된 버전, 확인일과 확인자를 증빙으로 기록합니다
- 인원 대조가 핵심이다 → 입장 인원과 퇴장 인원이 일치해야 허가를 반납할 수 있습니다
- 반납이 아니라 수색이다 → 퇴장 인원이 일치하지 않으면 반납 처리 전에 미확인 인원의 위치를 확인합니다
- 읽지 못하는 증명서는 종이일 뿐이다 → 내용을 확인할 수 있도록 모국어와 한국어를 함께 제공합니다

표어형 문장을 만나면 넷을 확인한다 — 어떤 대상에 어떤 조건이 적용되는가 · 누가 무엇을 확인하거나
기록하는가 · 조건을 충족하지 않으면 실제로 어떤 처리가 제한되는가 · 사용자가 해야 할 조치는
무엇인가.

**법령·교육 자료의 공식 표어, 캠페인 문구, 실제 인용문은 임의로 바꾸지 않는다.** 화면 안내·경고·
도움말·설계 노트에서는 공식 문구가 아닌 한 구체적인 조건과 처리 결과를 쓴다.

## V. 내부 구현 표현을 사용자 안내에 내지 않는다

개발자에게는 익숙하지만 **일반 사용자가 알 필요가 없는 데이터 구조·컴포넌트 구현·내부 처리
은유**를 사용자 문구에 쓰지 않는다. 「공용 응답 세트」·「검사가 돈다」·「필드가 규칙을 찾는다」·
「값이 깨진다」·「비밀값이 회전한다」는 사용자의 행동과 결과를 설명하지 못한다.

- 값은 공용 응답 세트를 그대로 씁니다 → 각 항목에서 「이상 없음」 또는 「이상 있음」을 선택합니다
- 검사는 하나도 돌지 않습니다 → 해당 필드에 검증 규칙을 적용할 수 없습니다
- 규칙이 필드를 찾지 못합니다 → 의미 태그가 없어 해당 필드에 검증 규칙이 적용되지 않습니다
- 오타로 변수가 깨집니다 → 변수명 오타로 값을 불러오지 못할 수 있습니다
- 비밀은 서비스 계정 화면에서 회전합니다 → 서명용 비밀값은 서비스 계정 화면에서 변경합니다

**관리자·개발자용 화면에서 사용자가 실제로 설정하는 기술 용어는 유지한다** — API·Webhook·
HMAC-SHA256·지수 백오프·병합 변수. 다만 그 용어가 든 문장도 전송·검증·변경·재시도처럼 실제
동작을 나타내는 서술어를 쓴다.

**내부 노트에서는 구현 결정을 설명하려고 컴포넌트명이나 데이터 구조를 쓸 수 있다.** 그 경우에도
「검사가 돈다」·「화면이 연다」·「데이터가 탄다」 같은 비유 대신 어떤 값에 어떤 검사를 적용하고 어떤
상태를 표시하는지 구체적으로 쓴다.

## W. 법정·전문 용어를 짧은 UI 명사로만 제시하지 않는다

> 화면 문구 전용 — 문서에는 이 자리가 없다.

법정 용어와 기술 용어는 정확히 유지하되, **일반 사용자가 대상과 효과를 알 수 있도록 문장 안에서
설명한다.** 일상에서 자주 쓰지 않는 법정 용어를 탭·배지·열 이름에 단독으로 두면 무엇이 무엇을
대신하는지 알 수 없다.

- 갈음 → 다른 의무 이행으로 인정
- 갈음 판정 → 다른 기록으로 이행한 의무 확인
- 이 입력이 갈음하는 의무 → 이 제출로 이행한 것으로 인정되는 의무
- 원본이 만료되면 갈음도 사라집니다 → 원본이 만료되면 대체 인정도 종료됩니다
- 교육 이수 갈음 → 다른 교육·자격을 해당 교육 이수로 인정

법적 근거를 설명하는 본문에서는 **「A 기록으로 B 의무를 갈음합니다」처럼 대상 A와 B를 모두
밝힌다.** 목록의 짧은 상태값이 필요하면 「다른 기록으로 이행」·「대체 인정」·「별도 제출 불필요」처럼
사용자가 바로 이해할 결과를 먼저 표시하고, 상세 설명에서 법정 용어와 근거를 제공한다.

**이 판정은 도메인마다 목록이 다르다** — 어느 용어가 라벨로 서면 안 되는지는 그 프로젝트의
용어사전(`.claude/GLOSSARY.md`)에 등재해 기계가 잡게 한다.

## X. 술어는 그것이 덮는 주어 전부에 맞아야 한다

주어가 둘 이상인 문장은 **술어를 각 주어에 따로 붙여 읽는다.** 하나에만 맞는 술어를 둘에 걸치면
문장은 매끄럽게 읽히면서 절반이 틀린다 — 규칙도 렌즈도 잡지 못하고, 나눠 읽어야만 드러난다.

| 이렇게 쓰지 않는다 | 왜 | 이렇게 쓴다 |
| --- | --- | --- |
| 톨루엔과 소음은 그 사람이 실제로 **마신** 양이 아닙니다 | 소음은 마실 수 없다 | 톨루엔과 소음은 그 사람이 실제로 **노출된** 양이 아닙니다 |
| 파일과 링크는 만료되면 **삭제됩니다** | 링크는 삭제가 아니라 무효가 된다 | 파일은 삭제되고 링크는 만료됩니다 |
| 담당자와 기한을 **선임합니다** | 기한은 선임하는 것이 아니다 | 담당자를 지정하고 기한을 정합니다 |

**주어를 하나로 줄이거나 술어를 둘로 나눈다.** 어느 쪽이든 「A와 B는 …한다」를 「A는 …하고 B는
…한다」로 펴 보고 두 문장이 다 참인지 확인하는 것이 판정 방법이다.

## Y. 한 동작에 이름은 하나다

같은 동작을 부르는 이름이 화면군마다 다르면, **낱말 하나만 보아서는 어느 것도 틀리지 않았다.**
「연결」도 「잇기」도 「붙이기」도 정상적인 한국어이므로 규칙이 잡을 근거가 없고, 잘못은 낱말이
아니라 낱말들 사이에 있다.

- **한 화면 안에서 동작과 그 반대가 다른 어근을 쓰면 이미 갈린 것이다** — 「잇기」 옆의 「연결
  끊기」, 「담기」 옆의 「빼기」.
- **행 동작·버튼·탭·화면 이름·지표 라벨을 한 줄로 늘어놓고 센다.** 가장 많이 쓰인 이름으로
  통일하고, 화면 이름을 바꿨다면 그 이름을 적어 둔 목차·명세·계획 문서를 같은 변경에서 함께 고친다.
- **비유인 쪽을 버린다.** 잇다·붙이다·걸다는 물건을 다루는 말이고 연결·지정·등록은 관계를 그대로
  말한다. 셋이 섞여 있으면 통일 대상은 언제나 뒤쪽이다.

찾는 방법은 읽기가 아니라 세기다 → [ui-copy-sweep.md](ui-copy-sweep.md) 6단계.

## Z. 없는 기능은 어디에 없는지를 대지 않는다

> 화면 문구 전용 — 문서에는 이 자리가 없다.

만들지 않은 기능을 「이 빌드에 없음」·「이 설치본에 없음」·「제품에 아직 없음」처럼 **어디에** 없는지
대면, 읽는 쪽은 **다른 데는 있다**고 읽는다. 설정을 뒤지고, 상위 상품을 묻고, 다시 설치한다.
코드에 없어서 없는 것이면 그 셋은 전부 헛걸음을 시키는 단서다.

**한 가지로 쓴다 — 「아직 없음」·「아직 없습니다」.** 「아직」이 그 자리에서 참인 유일한 말이다:
지금은 없고 만들면 생긴다. 「이 빌드」는 그 위에 [V절](#v-내부-구현-표현을-사용자-안내에-내지-않는다)의
잘못을 더한다 — 설치하는 사람은 빌드를 세지 않는다.

**정말로 자리에 따라 다른 것은 갈라 쓴다.** 가르는 기준은 낱말이 아니라 **읽는 사람이 할 수 있는
일이 있는가**이다.

| 무엇 | 그 사람이 할 일 | 문구 |
| --- | --- | --- |
| 코드에 없다 | 없다 — 기다린다 | 아직 없음 |
| 함께 왔는데 깔지 않았다 | 깔면 열린다 | 설치되지 않음 |
| 권한이 없어 보이지 않는다 | 권한을 청한다 | 볼 수 있는 권한 없음 |
| 이 프로젝트·이 계정에 없다 | 다른 곳에서 찾거나 만든다 | 이 프로젝트에 없음 |

**배지가 아니라 절인 자리에는 낱말을 끼우지 말고 서술어로 푼다.** 「이 빌드는 내보내기 파일을
만들지 않습니다」에 「아직 없음」을 끼우면 문장이 서지 않는다 — 「내보내기 파일은 아직 만들지
않습니다」로 쓴다. 짝이 되는 긍정 라벨도 함께 줄인다: 「이 빌드에 있음 / 없음」은 「있음 /
아직 없음」이다.

**규칙으로는 잡히지 않는다** — 셋 다 정상 한국어이고 뜻도 맞다. 세는 것으로 찾고
([ui-copy-sweep.md](ui-copy-sweep.md) 6단계), 그 프로젝트가 쓰던 철자를 프로젝트 용어사전의
`## 금지 표현`에 등재해 다음번은 기계가 잡게 한다.

## UI 요소별 문체

> 화면 문구 전용 — 문서에는 이 자리가 없다.

| 요소 | 문체 |
| --- | --- |
| 화면명·탭·배지 | 대상을 가리키는 짧은 명사형 |
| 버튼·행 작업 | 사용자가 실행할 구체적인 동작명 |
| 필드 라벨 | 입력하거나 표시하는 값의 이름 |
| 설명 | 화면에서 확인하거나 처리하는 내용 |
| 경고 | 문제, 영향, 필요한 조치 |
| 도움말 | 개념, 적용 조건, 예외, 판단 기준 |
| 내부 메모 | 생략 없는 완전한 설명문 |

같은 정보를 요소마다 반복하지 않는다. 화면명에 대상이 이미 분명하면 설명에는 사용자가 확인하거나
수행할 일을 적는다.

**필드 라벨은 질문이나 조건절이 아니라 값의 종류다** — 무엇을 하면 열리는가 → 제한 해제 조건 /
왜 위험한가 → 운영 위험 / 다시 연결되면 → 재연결 후 처리 / 끌 수 있는가 → 비활성화 가능 여부 /
그대로 두면 → 미조치 시 영향. 라벨과 값이 `항목명: 값`으로 읽히게 쓴다.

**상태값과 동작명을 구분한다.** 오프라인·미이수·차단은 상태이고, 재연결 후 동기화·교육 배정·제한
해제는 동작이거나 처리 결과다. 상태 이름도 비유에 기대지 않는다 — 관문 열림 → 배정 가능 또는 출입
가능 / 관문 닫힘 → 배정 제한 / 정책 뒤짐 → 정책 미동기화 / 장치 침묵 → 데이터 미수신 / 허가가 열린
채로 남음 → 이용 허가 미반납. **같은 「열림」이 출입 가능·편집 가능·승인 완료·기능 활성화를 뜻할 수
있으므로 실제 상태로 갈라 적는다.**

**설명과 버튼이 같은 동작을 다른 이름으로 부르지 않는다** — 경고 「검사를 신청하세요」 + 버튼
「검사 일정 잡기」는 둘 다 「검사 신청」이다.
